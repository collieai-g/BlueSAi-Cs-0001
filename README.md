# BlueSAI-客服

**BlueSAi-Cs-#0001 · 0.4.0-preview.1 · MIT**

BlueSAI 是配合目前 Codex／DOT 的**客服專用工作介面與持久工作環境（harness）**：左側理解及運用當次可用工具，右側保留商戶知識、來訊、草稿與真實處理結果，本人跨兩邊指揮與核對。產品的價值在完整客服工作的連續性；底層模型、渠道執行器與介面各有自己的責任。[產品定位、左右協作與開發指示](docs/HARNESS_ENGINEERING.md)

客服是 **Blueprint Studio → AI → Agent 工作台中的一個卡片項目**。精簡入口展開為同一實例的客服工作區，主要檢視是「收件匣／知識庫／管理」；對話與設定都留在這張卡片內。

**宿主的「總覽、工作、資料」保持由工作室管理。客服安裝不得替換這些內容、導覽、路由或資料表。** 固定邊界見 [Agent 介面及資料合約](docs/AGENT_UI_CONTRACT.md)。

## 卡片內容

- **收件匣**：對話列表、訊息、待確認草稿及人工回覆；上下文按空間以側欄或抽屜呈現。
- **知識庫**：建立已核對 FAQ、教客服及批准記憶；未確認、過期或衝突內容不供直接回答。
- **管理**：商戶實際資料、回覆政策及渠道狀態；WhatsApp、網頁與選用模型各有自己的接駁流程。未知資料保持空白。

知識庫另提供「從人工對話學習」：成功提交的人工示範可由模型提煉為待確認的商戶事實、處理流程或回覆風格，經本人編輯／批准後使用。FAQ 未命中時，已接駁的 AI 可理解不同問法；流程指導先確認哪些資料，不能當成到貨日期等事實來源。自動整理預設關閉，學習不等於自動批准或開啟發送。[操作、來源與安裝界線](docs/KNOWLEDGE_LEARNING.md)

展開卡片先處理收件匣；管理表單不擠進日常對話。交互參考 Zendesk 的同頁對話及上下文方式，保留 Blueprint 視覺，沒有接入 Zendesk。FAQ 優先處理唯一吻合、已確認且仍有效的答案；沒有命中時，才按另外開啟的設定使用 AI 或交本人處理。接收、回覆範圍、FAQ 自動發送及 AI 自動發送各自確認。[完整運作邏輯與通知界線](docs/LIVE_INBOX.md) · [介面規格與參考](docs/UI_DESIGN.md)

## 三種回覆路線

| 路線 | 如何產生回覆 | 需要甚麼 |
| --- | --- | --- |
| FAQ-only／人工 | 已批准且問題完全吻合的答案直接採用；沒有答案便交本人，仍可手動交目前 DOT 準備草稿 | 不需模型或 API key；真正收發仍需運行中的客服與渠道 |
| 本機原生 Codex CLI | FAQ 沒命中後，由獨立、受限的 CLI 工作讀取單一客戶有限資料及已批准知識 | 本機 Codex CLI、可用的 ChatGPT 登入、本人同意的合成測試；使用帳戶額度，不另要求 API key |
| 選用模型 API | FAQ 沒命中後，使用本人另行配置的模型 API | 自己的 API key、可用模型及相應 API 額度 |

原生 CLI 工作不會喚醒、讀取或控制目前左側 Codex／DOT 聊天，也不提供通用跨 AI 接續。`aiFallback` 與 `automaticAi` 預設關閉；接駁成功不會修改政策或直接打開自動回覆。有已批准來源的 `answer` 才有資格按授權自動發送，澄清先存草稿，退款／衝突／缺依據／失敗或逾時轉人工。[啟用、執行限制與復原](docs/INSTALL.md#原生-codex-與選用-api)

## 本機啟動

客服核心需要 **Node.js 24.22+（24.x）**，沒有第三方 npm 依賴；選用的 Codex CLI 與 WhatsApp 橋接須另外準備及核對，啟動核心不會替本人安裝或登入它們。

```sh
npm start
```

開啟 [http://127.0.0.1:3100/](http://127.0.0.1:3100/)，只顯示客服卡片；`/workbench.html` 是同一卡片入口。`/console` 也回到卡片。管理員密碼保存在倉庫外 `BLUEPRINT_DATA_DIR/admin-token`，預設資料目錄為 `~/.blueprint-service`；在本機安全讀取，毋須貼到聊天。

`npm run workbench` 保留 3101 隔離卡片預覽，沒有收發 worker。舊整頁管理工具只保留在獨立服務的 `/diagnostics/console` 供明確診斷，**不作為 Agent 的介面或安裝成果**。

本機卡片與真正工作室安裝是兩個驗收項目。此 Node 服務為一商戶、一程序及一份私人 SQLite，不可共用給不同商戶。上述預設資料目錄只供該本機實例；新工作室必須另設獨立空白私人目錄，不能把新卡片指向這個既有核心或共用預設目錄。

本機原生模式須讓電腦、客服核心及 WhatsApp 橋接持續運行，並能連至模型服務；關閉目前聊天不會停止已獨立運行的 CLI 工作，但電腦關機或服務停止便不能繼續。這不是雲端部署。將來可選可信的常駐執行環境或模型 API 路線，另行設定身份、儲存與渠道，不搬移本機登入檔、不由 GitHub 推送推斷已部署。

## 真正 WhatsApp 測試

目標是 **本人手機掃碼 → 指定測試號碼來訊 → 卡片核對／人工回覆 → 測試手機實際收到**。離線規則、網頁扮演客人、模擬 provider 和教學閱讀進度都不能代替這項驗收。

接駁方式及必要服務見 [WhatsApp 執行路線](docs/WHATSAPP_RUNTIME.md)；卡片操作見 [接駁教學](docs/CONNECTION_GUIDE.md)。沒有運行中的真實接駁服務時，會列出缺項，不提供示意 QR 當作已連接。只完成手機連結時不宣稱已能收件或送達。

初次發送維持關閉。先設定本人指定的測試收件號碼／allowlist，再依當次授權開啟測試發送；不把整個手機通訊錄當成測試對象。結果不明不盲目重發。

暫時沒有另一個帳戶時，可先用「自己傳給自己」核對真實收件，預設只讀。要試回覆，再明確開啟獨立「本人對話回覆測試」：用手機重新傳一則新 Hello，可測已批准 FAQ 的自動回覆及專用人工回覆，不需模型或 API key，亦不呼叫 CLI／API／DOT。舊 Hello 不會重跑；測試另列、不計入客戶待處理，也不代替外部顧客雙向驗收。重啟、斷線、換帳戶或撤銷後重新確認。[快速操作與停止條件](docs/SELF_REPLY_TEST.md)

## 安裝到既有工作室

公開 GitHub 及版本套件只交付可重用程式、文件及合成測試材料。商戶知識、FAQ／學習資料庫、對話、帳戶記錄、WhatsApp 真實來源及登入、私人設定和備份都留在各自的私人執行環境，不能隨程式發佈或複製到另一工作室。

把 [INSTALL_AI.txt](INSTALL_AI.txt) 交給目前安裝 AI，先核對真正工作室與公司，再選下列流程；不可把新安裝當成舊本機服務的另一個入口。

| 情況 | 資料與接駁 |
| --- | --- |
| 新工作室／新商戶（fresh） | 新的空白核心私人目錄及獨立 runtime；另設橋接私人目錄、帳戶／instance、憑證及 callback，由本人重新連結該工作室的 WhatsApp。商戶欄位及知識空白，自動處理／發送須重新確認；不指向舊核心、共用預設目錄或複製舊資料／auth |
| 同一工作室升級（upgrade） | 核對同一公司及 Agent 後，保留原私人目錄、知識、對話及橋接登入；先備份，再作增量 schema 更新與讀回。不要每次清空或重新掃碼；失效登入及重啟後的程序內授權另按實際狀態處理 |

新工作室須讀回全新空白資料及新的 runtime／渠道綁定；同一工作室升級則讀回原資料保留。[具體安裝分流](docs/INSTALL.md#新工作室與同工作室升級)

套件內 `integrations/blueprint/agent.json` 是可登記的協作 manifest，根目錄 `agent.json` 是產品身份。收件匣工作區的原生 renderer 與公司固定的受限 API 仍須由真正宿主支援；單靠登記 manifest 不會產生這些能力。[安裝套件](docs/INSTALL_PACKAGE.md) · [完整安裝指引](docs/INSTALL.md)

**完整通用 Sites D1／R2 客服管理適配尚未交付。** 缺少 renderer、接口或持續執行器時，應明確說明「目前不能運行」的原因及下一步；不能用客服整頁、iframe 或覆蓋宿主主列避開限制。本版沒有宣稱私人測試工作室已修改或已安裝。

## 驗證

```sh
npm test
npm run check
```

模擬測試證明程式在指定條件下的行為；真實手機、收件及送達須保留當次證據。來源固定 commit、GitHub 推送、宿主部署、卡片可見和 WhatsApp 真實收發分別回報。[架構](docs/ARCHITECTURE.md) · [卡片尺寸與原生整合](docs/BLUEPRINT_PLUGIN_DESIGN.md) · [開發次序](docs/DEVELOPMENT_PLAN.md)

密鑰、手機登入狀態、SQLite、日誌、備份及私人部署身份均留在 Git 之外。Blueprint 共用視覺資產與 MIT 聲明保留於 [UI_SOURCE.json](UI_SOURCE.json) 及 `public/vendor/`。

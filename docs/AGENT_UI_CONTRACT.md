# 客服 Agent 卡片與宿主資料邊界

版本：0.4.0-preview.2。介面合約修訂：2026-10-30。這是客服介面、安裝和後續更新的固定合約。

## 一個 Agent 項目、一張卡片

正式位置為 **Blueprint Studio → AI → Agent 工作台 → BlueSAI 客服卡片**。精簡入口與展開工作區是同一個已登記 Agent 的兩種狀態；不建立另一套工作室或另一個客服管理網站來取代宿主。

展開後優先進入**收件匣**，主要檢視為「收件匣／知識庫／管理」。收件匣處理來訊、草稿、人工接手及回覆；知識庫管理已確認 FAQ 及待核對記憶；管理包含商戶資料、全域回覆政策、渠道狀態與接駁教學。這取代舊「基本設定／訓練／接駁」的導覽規則；程式可以保留舊內部 ID 作相容。WhatsApp、網頁及離線規則各按實際渠道標示，不混用驗收結果。

卡片只渲染自己的根節點。外層側欄、頂列、主導覽、公司切換、工作室背景及排版由宿主負責。本機卡片頁也不模擬一整套宿主導覽。

原生宿主以同一個 Agent ID 建立一個穩定的排版外框，並透過 `context.cardTarget` 提供專用掛載區。已審閱且由宿主明確載入的 renderer 使用 `BlueprintAgents.registerCardRenderer(id, renderer)` 登記，核對固定來源與私人 binding 後才掛載；Agent manifest 不能提供任意腳本網址。客服不得把自己的卡片直接插到通用設定表單旁。宿主將版本、通用設定及工作保留在同一外框的「進階 Agent 設定與工作」，不把它們拆成額外排版卡片。欠缺專用接口、版本不符或掛載失敗時，明列原因並保留通用入口；不以整頁替換或隱藏必要控制繞過。

精簡／展開切換沿用同一客服 DOM，由 renderer 提供尺寸規格、宿主調整同一外框。離開再返回時保留未送出輸入及選定內容；帳戶更換仍須清理舊帳戶元件與工具。這是來源整合契約，指定實例是否已採用須另外核對，不能由文件或登記結果推斷。

## 收件匣交互

- 入口只保留客服身份、真實渠道狀態、後台待處理數量及「開啟收件匣」主要操作；管理與接駁是次要入口。展開、返回和切換檢視不建立第二個 Agent 或重設選定對話。
- 展開主卡片固定 4:3，包含頂列、分頁、內容及頁尾；最小 576×432、預設 864×648、最大 1152×864 CSS px。收件匣、知識庫及管理共用同一外框；精簡入口仍採原有版面。收件匣永遠保留左右兩個工作區：左側對話／客戶諮詢佔約 28%，限制在 176–288px；右側訊息及回覆使用餘下空間。詳情維持卡片內抽屜，不再於寬卡片自動變第三欄。畫面不足 576px 時保留最小卡片並水平捲動，不隱藏任一工作區或使用列表／詳情二選一。
- 列表按真實資料顯示渠道、名稱、最近文字、時間及處理狀態。待處理不是未讀；篩選及數量不得編造。搜尋只涵蓋當前已載入對話，不能宣稱搜尋手機舊歷史。卡片不提供尚無後台支援的 CRM 屬性、分派、SLA 或結案操作。
- 上下文只展示目前對話、有效知識來源、處理方式及渠道發送條件；缺項直接連至管理中的相關步驟。自動更新保留各客戶未送出的回覆、草稿編輯、選取及閱讀位置，不搶走焦點。
- 知識庫答案只在唯一完整問題吻合、答案已批准且仍有效時採用；自動發送另經全域政策及當前渠道授權。DOT 僅讀取本人選定對話，先讀最新版本再保存草稿；採用與發送是另外的明確操作。
- FAQ-only、原生 Codex CLI 與模型 API 分開呈現。原生 CLI 是本機獨立受限工作，使用既有 ChatGPT 登入及帳戶額度，不控制目前左側聊天，也不代表宿主原生卡片已安裝。接駁測試成功不改政策；aiFallback／automaticAi 預設關閉，有批准來源的 answer 才可按獨立渠道授權自動發送，clarify 留草稿，退款／衝突／無依據／失敗／逾時轉人工。
- WhatsApp 自傳測試在「連線測試」檢視另列，預設只讀，不計入客戶待處理或通知。另行明確同意的「本人對話回覆測試」以當次帳戶綁定隨機 grant，僅開放新自身文字的 exact-approved FAQ 自動回覆及專用人工回覆，自動 FAQ 另需全域 enabled／automaticKnowledge，不觸發 CLI／API 或 DOT。人工切至 self_human，交回 self_auto 只作用下一筆新來訊；舊 Hello 不重跑。回聲按 ID＋address 攔截，uncertain 自停，重啟／斷線／換帳戶／撤銷關閉授權；不改外部顧客 scope，不作外部收發驗收。見 [SELF_REPLY_TEST.md](SELF_REPLY_TEST.md)。

交互參考為 [Zendesk Agent Workspace 官方說明](https://support.zendesk.com/hc/en-us/articles/4408821259930-About-the-Zendesk-Agent-Workspace/) 及[使用者提供的官方示範](https://www.zendesk.hk/demo/)。只借鑑同頁處理對話、知識及上下文的方式，沿用 Blueprint 視覺與本產品權限；不整合 Zendesk、不複製其素材，也不宣稱具備示範中的全部功能。

## 管理分區與接駁步驟

管理在所有尺寸均保留左側分類與右側內容；左側約佔 20%，限制在 144–208px，分類文字持續存在。右側設定與左側分類各自在同一外框內垂直捲動，不轉成上方分類列。管理只在客服根節點內提供「渠道接駁／回覆方式／AI 與助手／商戶資料／測試與提示」五個分類，以及固定位置的內容工作面。分類寬度隨卡片可用尺寸調整，工作區高度依主卡片剩餘高度分配。這是客服內部導覽，不新增或覆蓋宿主的側欄、頂列及全域路由。

- 「渠道接駁」總覽顯示目前已連結電話、手機連線燈與實際收件範圍；已連接為綠燈、未連接為紅燈，未知狀態不可當成已連接。紅／綠燈緩慢變化明暗，遵守減少動態偏好。電話須來自當前帳戶的後台讀回，關閉、錯誤、重新配對或未提供時不沿用舊值。連線燈不證明收件、發送、模型或送達；收件需獨立核對本人同意及入口。
- WhatsApp 主流程由一次明確按鍵開始，在原位顯示準備服務、真實 QR、等待手機確認及已接駁；不再以可跳選的四步表單作主要入口。開頁、返回或切換分類不會自動準備服務、連線、取碼、建立任務、授權收發或發送。網頁渠道仍沿用自己的教學。
- 本機準備使用後台固定的程式入口及事先安裝的固定依賴，只啟動該預覽擁有的 bridge，私人設定與資料留在該預覽專用的 Git 外目錄；不讀取或共用其他工作室的帳戶、auth、資料或渠道程序。API 不下載或安裝依賴，缺少依賴或準備能力時明列缺項並提供進階設定，不偽造 QR 或成功狀態。安裝指引及一般 Codex／DOT 任務仍分開使用，草稿不表示已執行安裝。
- 只有當前後台讀回 `open` 及有效核對時間才可標為手機已接駁；不能由 QR、掃碼動作、服務啟動或輪詢逾時推斷成功。本機 bridge 啟動就緒確認最多等待十五秒，後續狀態檢查及失敗清理另有限時，不能把十五秒寫成整個準備工作的總時限。頁面準備等待與連線等待亦有上限；重試核對原結果，失效或錯誤不刪 auth、不無限重連。取消只停止頁面等待並清 QR，不停止已開始的後台準備或解除手機授權。
- 商戶、模型、回覆政策、收件／回覆同意、本人測試及通知操作仍使用受限 API。指定測試號碼表單與切回測試名單的操作退出卡片流程；新私人文字收件及最近來訊回覆須在流程內各自明確同意，不能因移除名單便自動啟用。切換分類或步驟保留原 DOM 表單、尚未儲存的輸入與同意選項；不得以重建內容造成輸入遺失。
- 全域 FAQ／AI 政策、單一對話人工／自動控制、渠道發送範圍及本人測試授權各自獨立；版面切換不授予任何操作權限。

分類與表單內容的功能對應見 [UI_DESIGN.md](UI_DESIGN.md#管理的分區工作面)。新版來源、生成資產、空白本機測試及指定既有實例更新分開驗收；來源改版不代表任何私人工作室已更新。

3101 本機工作台可準備獨立 bridge、顯示真實 QR、核對手機狀態，並在手機連接後自動準備新私人文字收件；只有入口及同一帳戶核對成功才顯示收件中。本人可對最近來訊人工回覆，或由已啟用的知識庫／AI 政策自動回覆；本機沒有額外強制草稿限制。連線本身不更改已保存政策。受限本機 Codex 仍需本人同意及獨立檢查；手機連接或合成推理成功不等於真實收件或送達驗收。

## AI 與助手選擇

介面保留本機登入、模型 API、目前 Codex／DOT 任務三個入口，縮短主要說明並把長篇限制放在可展開內容；保留原有同意、測試、停用、任務及草稿控制，不能以精簡版面改變權限。流程示意與後台狀態分開，減少動態偏好仍有效。

本機助手可選 Codex、Grok、Claude；目前只有 Codex 有受限 adapter。Grok／Claude 的選項只提供真實未支援狀態及指引草稿，未檢查安裝、登入或推理，不能提交接駁，不能呼叫 Codex 或模型 API 代替。切換候選選項會清除該次同意，不變更目前 adapter；停用與狀態仍指向後台正在使用的路線。

新版 3101 入口只由伺服器注入可信 `nativeAgentFactory` 並明確設定 `allowNativePreview`，獨立提供 Codex 檢查能力；`runtime`／`runtimeMode` 及收發 worker 維持原模式。`nativeAvailable` 只表示本服務提供該檢查入口，不證明 CLI 已安裝、已登入或可推理。既有 `POST /api/agents/bluesai-cs-0001/connections/native-codex` 僅在登入、同源及 `{consent:true}` 符合時執行版本、ChatGPT 登入與合成推理檢查，成功才切換 adapter；失敗保留原 provider、政策及資料。執行檔只由可信伺服器設定指定，使用同一預覽的 Git 外臨時工作目錄；CLI 自行沿用既有登入，卡片不讀取或搬移憑證，不增加模型工具或收發權限。

API 供應商可選 OpenAI、Anthropic、Google Gemini 或其他；目前只有 OpenAI 已有實際 adapter。未支援項目只作選擇及說明，必須阻止提交，不連接、不測試、不把金鑰交給另一供應商。OpenAI 模型提供 `gpt-6-luna`、`gpt-6.1-sol` 靜態參考選項及自訂輸入；未查詢帳戶模型清單，選項不證明帳戶權限、產品實測或實際可用性。本機 Codex 使用帳戶預設模型，與此 API 選單分開。

選擇供應商／模型本身不讀取或提交金鑰、不發出模型請求、不切換現有 adapter，也不更改 FAQ／AI 後備／自動發送政策。真正 API 檢查只由本人對支援路線明確提交後進行；失敗保留原路線，狀態按實際結果顯示。金鑰沿用密碼輸入及伺服器記憶體邊界，不放入網址、一般任務、日誌、公開來源或草稿。

AI 整理接駁指引只填入可編輯的 Codex／DOT 任務草稿；已有未儲存內容時保留，不自行建立任務、呼叫模型、安裝 adapter、建立金鑰或更改私人工作室。本人另按「準備任務」及明確交接後才處理。本機 CLI 的獨立受限推理與目前左側聊天仍分開，入口可見不代表已安裝、已登入或推理成功。

## 允許與禁止的寫入

| 範圍 | 允許的動作 |
| --- | --- |
| 指定客服 Agent | 使用固定 `bluesai-cs-0001` 及原有 instance ID 登記／更新自己的設定；依宿主版本檢查讀回 |
| 客服私人資料 | 商戶客服設定、已批准記憶、指定渠道對話、草稿、交接及回執；單商戶單程序儲存 |
| 卡片排版 | 只更新自己卡片的有效位置及尺寸；經宿主排版接口處理碰撞及保存 |
| 宿主「總覽／工作／資料」 | **禁止以客服頁面取代、覆蓋、清空或重新排版宿主內容** |
| 宿主業務資料庫及通用 API | **禁止直接共用或改寫宿主表、代理整個 `/api`、覆寫全域路由、導覽或 CSS** |

客服採用既有工作室資料時，只能經明確授權、公司固定、來源可撤銷的受限整合讀取；讀到資料不會取得覆寫宿主資料的權限。空白商戶欄位、原有批准、人工接手及歷史保留。

## 卡片接口

卡片前端只呼叫 **`/api/agents/bluesai-cs-0001`** 命名空間，包括該實例登入、設定、記憶、指定對話、草稿及接駁操作。宿主掛載時由經審閱的 adapter 綁定目前公司與 instance；不能相信瀏覽器傳來的公司 ID，也不能把 owner token 放進前端。

本機服務內部保留的 `/api/workbench`、舊 `/api/state` 等相容路由，並非授權宿主把全域 `/api` 交給客服。舊整頁工具只可在獨立服務的 `/diagnostics/console` 明確開啟診斷；它不屬於安裝產物的宿主介面。

## 能力不足時必須說清楚

| 實際缺項 | 畫面／交付要說明的結果及下一步 |
| --- | --- |
| 宿主未支援卡片 renderer 或受限 API | 只能列為待整合；先補指定接口及權限。不能搬整頁客服、iframe 或覆蓋宿主主列避開限制 |
| WhatsApp 連線服務未安裝／未運行 | 不能取得真正二維碼；列出缺少服務及啟動步驟，不顯示示意二維碼作成功 |
| 手機未完成掃碼 | 等待本人連結裝置；不能把配置齊全寫成手機已連接 |
| 收件入口未核對 | 列出 callback、驗證及可達性缺項；手機 open 不等於客服收到來訊 |
| 收件或最近來訊回覆未獲同意 | 可檢查手機連線及準備草稿；到設定收件步驟明確選擇授權，不能由綠燈推斷可收發 |
| 供應商只接受訊息 | 顯示 accepted；收到可對應回執或收件手機證據後才記錄送達 |

真實 WhatsApp 驗收要包含本人掃碼、明確收件及回覆同意、另一個已授權帳戶來訊、卡片讀回同一筆訊息、人工核對回覆，以及收件手機實際收到。毋須在卡片登記指定測試號碼。離線答案、網頁扮演客人、模擬 provider 或已推送 GitHub，均不能代替這份證據。

本合約不宣稱私人測試工作室已修改或已完成原生安裝。來源、登記、宿主部署、手機連線及真實收發各按當次實際結果回報。

## 卡片資產與本機頁面分開

`tools/build-workbench.py` 從同一份設計產生兩類資產。`public/agent-card.html` 只有客服根節點的元件標記，沒有文件外殼、登入頁或 script；`public/agent-card.css` 只有 `#cs-card-design` 內的樣式，不含 `body` 或 `.local-login` 規則。客服腳本沿用 `workbench-api.js`、`agent-handoff.js`、`inbox-tools.js`、`workbench.js`，不複製另一份腳本。

`integrations/blueprint/card-ui.json` 列出這六個經審閱的來源資產，以及必要的 `bluesai-management/1` renderer、`bluesai-management-api/1` 和客服專屬 API 命名空間。這是資產邊界，狀態仍為 `requires_setup`；宿主須實作及審閱原生 renderer，不能直接注入 HTML／script 或用 iframe 代替。

`public/workbench.html`、`public/workbench.css` 只供獨立本機卡片頁使用；`public/index.html`、`public/app.js`、`public/style.css` 是診斷整頁資產。以上全部禁止加入宿主卡片介面 bundle。不能以複製整個 `public/` 或全域 CSS 的方式安裝客服卡片。

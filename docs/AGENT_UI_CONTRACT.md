# 客服 Agent 卡片與宿主資料邊界

版本：0.4.0-preview.1。介面合約修訂：2026-10-26。這是客服介面、安裝和後續更新的固定合約。

## 一個 Agent 項目、一張卡片

正式位置為 **Blueprint Studio → AI → Agent 工作台 → BlueSAI 客服卡片**。精簡入口與展開工作區是同一個已登記 Agent 的兩種狀態；不建立另一套工作室或另一個客服管理網站來取代宿主。

展開後優先進入**收件匣**，主要檢視為「收件匣／知識庫／管理」。收件匣處理來訊、草稿、人工接手及回覆；知識庫管理已確認 FAQ 及待核對記憶；管理包含商戶資料、全域回覆政策、渠道狀態與接駁教學。這取代舊「基本設定／訓練／接駁」的導覽規則；程式可以保留舊內部 ID 作相容。WhatsApp、網頁及離線規則各按實際渠道標示，不混用驗收結果。

卡片只渲染自己的根節點。外層側欄、頂列、主導覽、公司切換、工作室背景及排版由宿主負責。本機卡片頁也不模擬一整套宿主導覽。

## 收件匣交互

- 入口只保留客服身份、真實渠道狀態、後台待處理數量及「開啟收件匣」主要操作；管理與接駁是次要入口。展開、返回和切換檢視不建立第二個 Agent 或重設選定對話。
- 桌面以對話列表、所選訊息及回覆區、上下文構成工作區。864 CSS px 預設卡片採雙欄，上下文以抽屜開啟；可用內容寬達 1080 CSS px 才可同時顯示三欄。上下文不擠窄回覆欄，手機用列表／詳情及返回按鈕切換，上下文另開抽屜。
- 列表按真實資料顯示渠道、名稱、最近文字、時間及處理狀態。待處理不是未讀；篩選及數量不得編造。搜尋只涵蓋當前已載入對話，不能宣稱搜尋手機舊歷史。卡片不提供尚無後台支援的 CRM 屬性、分派、SLA 或結案操作。
- 上下文只展示目前對話、有效知識來源、處理方式及渠道發送條件；缺項直接連至管理中的相關步驟。自動更新保留各客戶未送出的回覆、草稿編輯、選取及閱讀位置，不搶走焦點。
- 知識庫答案只在唯一完整問題吻合、答案已批准且仍有效時採用；自動發送另經全域政策及當前渠道授權。DOT 僅讀取本人選定對話，先讀最新版本再保存草稿；採用與發送是另外的明確操作。
- FAQ-only、原生 Codex CLI 與模型 API 分開呈現。原生 CLI 是本機獨立受限工作，使用既有 ChatGPT 登入及帳戶額度，不控制目前左側聊天，也不代表宿主原生卡片已安裝。接駁測試成功不改政策；aiFallback／automaticAi 預設關閉，有批准來源的 answer 才可按獨立渠道授權自動發送，clarify 留草稿，退款／衝突／無依據／失敗／逾時轉人工。
- WhatsApp 自傳測試在「連線測試」檢視另列，只供閱讀；不計入客戶待處理、不觸發 FAQ、CLI／API 生成、DOT、人工／自動發送或待處理通知，不當作外部客戶收發驗收。

交互參考為 [Zendesk Agent Workspace 官方說明](https://support.zendesk.com/hc/en-us/articles/4408821259930-About-the-Zendesk-Agent-Workspace/) 及[使用者提供的官方示範](https://www.zendesk.hk/demo/)。只借鑑同頁處理對話、知識及上下文的方式，沿用 Blueprint 視覺與本產品權限；不整合 Zendesk、不複製其素材，也不宣稱具備示範中的全部功能。

## 允許與禁止的寫入

| 範圍 | 允許的動作 |
| --- | --- |
| 指定客服 Agent | 使用固定 `bluesai-cs-0001` 及原有 instance ID 登記／更新自己的設定；依宿主版本檢查讀回 |
| 客服私人資料 | 商戶客服設定、已批准記憶、指定渠道對話、草稿、交接及回執；單商戶單程序儲存 |
| 卡片排版 | 只更新自己卡片的有效位置及尺寸；經宿主排版接口處理碰撞及保存 |
| 宿主「總覽／工作／資料」 | **禁止以客服頁面取代、覆蓋、清空或重新排版宿主內容** |
| 宿主業務資料庫及通用 API | **禁止直接共用或改寫宿主表、代理整個 `/api`、覆寫全域路由、導覽或 CSS** |

客服採用既有工作室資料時，只能經明確授權、公司固定、來源可撤銷的受限整合讀取；讀到資料不會取得覆寫宿主資料的權限。空白商戶欄位、原有批准、人工接手及歷史保留。

## 卡片接口

卡片前端只呼叫 **`/api/agents/bluesai-cs-0001`** 命名空間，包括該實例登入、設定、記憶、指定對話、草稿及接駁操作。宿主掛載時由經審閱的 adapter 綁定目前公司與 instance；不能相信瀏覽器傳來的公司 ID，也不能把 owner token 放進前端。

本機服務內部保留的 `/api/workbench`、舊 `/api/state` 等相容路由，並非授權宿主把全域 `/api` 交給客服。舊整頁工具只可在獨立服務的 `/diagnostics/console` 明確開啟診斷；它不屬於安裝產物的宿主介面。

## 能力不足時必須說清楚

| 實際缺項 | 畫面／交付要說明的結果及下一步 |
| --- | --- |
| 宿主未支援卡片 renderer 或受限 API | 只能列為待整合；先補指定接口及權限。不能搬整頁客服、iframe 或覆蓋宿主主列避開限制 |
| WhatsApp 連線服務未安裝／未運行 | 不能取得真正二維碼；列出缺少服務及啟動步驟，不顯示示意二維碼作成功 |
| 手機未完成掃碼 | 等待本人連結裝置；不能把配置齊全寫成手機已連接 |
| 收件入口未核對 | 列出 callback、驗證及可達性缺項；手機 open 不等於客服收到來訊 |
| 發送開關或測試號碼未設定 | 可檢查連線及準備草稿；完成指定測試範圍後才可發送 |
| 供應商只接受訊息 | 顯示 accepted；收到可對應回執或收件手機證據後才記錄送達 |

真實 WhatsApp 驗收要包含本人掃碼、指定測試號碼來訊、卡片讀回同一筆訊息、人工核對回覆，以及測試手機實際收件。離線答案、網頁扮演客人、模擬 provider 或已推送 GitHub，均不能代替這份證據。

本合約不宣稱私人測試工作室已修改或已完成原生安裝。來源、登記、宿主部署、手機連線及真實收發各按當次實際結果回報。

## 卡片資產與本機頁面分開

`tools/build-workbench.py` 從同一份設計產生兩類資產。`public/agent-card.html` 只有客服根節點的元件標記，沒有文件外殼、登入頁或 script；`public/agent-card.css` 只有 `#cs-card-design` 內的樣式，不含 `body` 或 `.local-login` 規則。客服腳本沿用 `workbench-api.js`、`agent-handoff.js`、`inbox-tools.js`、`workbench.js`，不複製另一份腳本。

`integrations/blueprint/card-ui.json` 列出這六個經審閱的來源資產，以及必要的 `bluesai-management/1` renderer、`bluesai-management-api/1` 和客服專屬 API 命名空間。這是資產邊界，狀態仍為 `requires_setup`；宿主須實作及審閱原生 renderer，不能直接注入 HTML／script 或用 iframe 代替。

`public/workbench.html`、`public/workbench.css` 只供獨立本機卡片頁使用；`public/index.html`、`public/app.js`、`public/style.css` 是診斷整頁資產。以上全部禁止加入宿主卡片介面 bundle。不能以複製整個 `public/` 或全域 CSS 的方式安裝客服卡片。

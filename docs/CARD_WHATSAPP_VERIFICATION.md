# 單一卡片與本機 WhatsApp 驗證紀錄

版本：0.3.0-preview.2。日期：2026-10-25（香港）。

## 已完成

- 本機 `/` 及舊 `/console` 入口均開啟單一客服卡片；沒有複製工作室「總覽／工作／資料」導覽。
- 設定、訓練、渠道接駁及客服自己的對話均留在同一卡片。純元件資產與獨立登入頁分開；宿主資產 allowlist、固定 API 命名空間及禁止覆蓋宿主內容的規則見 `AGENT_UI_CONTRACT.md`。
- 舊資料已作 SQLite 一致備份；切換入口後核對原有設定、記憶及訊息內容一致。私人資料、token、WhatsApp auth、電話及 QR 均不在來源套件內。
- 本機隔離 Node 24.22.0 已實際匯入固定版本 Baileys 及 QR encoder。橋接只監聽 loopback，啟動時名單及發送閘門關閉。
- 本次確實從 WhatsApp provider 取得 QR；本人回報已掃碼後，卡片向服務讀回 `open`。客服核心重啟後再次讀回 `open`，未重新掃碼。
- 卡片登記本機收件設定後，服務讀回 callback、事件及授權設定相符；這不是客戶訊息送達的證明。
- Node 24 完整測試 130/130 通過，包含 13 項橋接測試及 8 項核心測試發送閘門測試；語法檢查通過。測試用假的 socket／provider 驗證協定及失敗情況，不冒充真人驗收。

## 尚欠真人操作及驗收

1. 在卡片填另一個本人持有或已獲同意的測試 WhatsApp 號碼，明確開放該號碼；空白名單不轉送客戶內文、不發送。
2. 從該號碼傳訊到已連結帳號，在卡片讀回同一筆新來訊。自傳、群組及歷史同步不屬於此測試。
3. 補齊本人商戶名稱、服務介紹及人工接手方式。原有空白欄位未被代填。
4. 在卡片接手並核對人工回覆，確認收件手機實際收到；供應商 accepted、delivered、read 分開記錄。不確定結果不自動重發。
5. 如要測試 AI 答覆，另行安全設定及驗證模型。沒有模型的離線示範不會代替真正 AI 驗收或自動發送至 WhatsApp。

這份紀錄截至上述人工驗收完成前，不宣稱真正訊息雙向收發或 AI 回覆已通過。

本次指定號碼曾與已連結帳戶相同，因此自傳訊息依設計被略過，沒有進入客服。介面已補清楚說明，橋接亦會在開放測試前拒絕同一帳戶，回報另一個帳戶的下一步。本人目前沒有另一個測試帳戶，要求保留手機連結稍後測試；測試發送及名單先關閉，不以舊有網頁／示範對話冒充 WhatsApp 來訊。

## 工作室安裝邊界

私人測試工作室尚未被修改，原生 renderer／受限 API 接入仍待實作及驗證。安裝工具維持 `requires_setup`；欠缺指定能力便停止並回報，不能以整頁、全域 CSS、iframe 或共用宿主資料庫來代替。GitHub 發布、私人工作室部署及 WhatsApp 訊息驗收各自獨立回報。

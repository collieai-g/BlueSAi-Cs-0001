# 客服卡片的真實接駁流程

版本：0.4.0-preview.2。介面修訂：2026-10-28。入口：AI → Agent 工作台 → 客服卡片 → 管理 → 渠道接駁。

管理先顯示已連結電話及手機連線燈；已連接的帳戶不必重新走完整教學。綠燈只表示手機已連接，紅燈表示未連接，狀態未明時顯示待核對；不代表已啟用收件、回覆或模型。下列完整流程供初次設定或需要重新接駁時使用。

本次 WhatsApp 驗收以真實手機收發為準。教學閱讀、離線規則、模擬 provider 及網頁聊天的結果各自標示，不當作 WhatsApp 完成證據。

## 在同一位置完成接駁

「管理」的五個分類為「渠道接駁／回覆方式／AI 與助手／商戶資料／測試與提示」。選擇分類後，右側工作面在原位顯示內容；窄畫面仍提供可見的分類選擇。切換不清空尚未儲存的表單或任務文字，也不提交任何設定。

「渠道接駁」總覽顯示手機連結與實際收件範圍。按 WhatsApp 主按鈕後，在原位完成「準備服務 → 掃描 QR → 等待手機確認 → 已接駁」，不再要求使用者逐一切換四個設定步驟。開頁、切換管理分類或瀏覽說明不會自行準備服務或連接手機；只有本人按下接駁才開始。紅／綠燈緩慢變化明暗，裝置偏好減少動態時保持靜態。

進階服務設定及安裝協助按需展開，不放在主流程前要求使用者手動填 URL、instance 或金鑰。需要 AI 整理安裝指引時，仍在目前渠道內開啟及返回；一般 Codex／DOT 任務及結果保留在「AI 與助手」。網頁接駁保持可見並沿用自己的教學。

## 接駁 WhatsApp

1. **按一次接駁，等待服務準備。** 支援本機準備的預覽會在本人按鍵後檢查固定程式來源及已安裝依賴，啟動該預覽專用的 loopback bridge；登入、資料及金鑰放在該預覽自己的 Git 外資料目錄，不從其他工作室複製。按鍵不下載或安裝依賴，缺少依賴時會明確提示先由安裝人員準備；已有可用服務時沿用其配置。未提供本機準備能力的宿主會說明缺項並提供進階選項，不能假裝準備完成。
2. **掃描真實 QR。** 服務就緒後，同一工作面顯示 provider 回傳的有效二維碼。在 WhatsApp 或 WhatsApp Business App 打開「已連結裝置 → 連結裝置」，完成身份確認再掃碼。iPhone 從設定或個人頭像進入，Android 從三點選單進入。已核對的有效既有連結毋須重新掃碼。
3. **等待本頁核對手機結果。** 頁面輪詢連線狀態；只有後台讀回 `open` 及有效的當次核對時間，才顯示已接駁與可用的連結電話。QR 出現、手機掃過或服務準備完成均不等於已接駁。QR 到期、登入失效、服務錯誤或等待逾時時，顯示固定原因與重試；不自動刪 auth 或無限重連。

本機服務啟動、狀態檢查及錯誤清理分別限時執行；頁面準備等候設有十分鐘上限，手機連線等待最多三分鐘。取消會停止本頁等待／輪詢並移除 QR；不停止已開始的後台準備、不解除手機授權，也不刪除登入資料。重新開啟或重試先核對已有結果，不能用取消或逾時推斷服務已停止。

### 手機已接駁之後

3101 本機工作台在手機連結成功後自動準備接收新一對一私人文字，無須填寫另一張收件表單；接收不依賴 AI 模型或 API。收件入口及已連結帳戶通過核對才顯示可接收；若準備失敗，介面提供重試。掃碼或模型推理成功本身不等於真實收件驗收。

驗收收發時，使用另一個本人擁有或已同意參與測試的 WhatsApp 帳戶傳送新文字；在同一卡片核對來訊，人工接手及核對回覆後，再到收件手機確認實際收到。provider accepted 不當成 delivered；結果不明先核對，不盲目重發。

| 本人操作 | 效果 |
| --- | --- |
| 已連接 WhatsApp | 本機自動準備接收新私人文字；毋須逐個登記號碼 |
| 已啟用知識庫／AI 自動回覆 | 下一則新來訊按已保存政策回覆；符合來源、版本及渠道條件的答案自動發送，人工接手優先 |
| 在對話按發送 | 只發送本人確認的該則回覆，限最近 24 小時主動來訊的客戶；不開放陌生主動訊息或群發 |

本機版本不再額外把知識庫或 AI 的自動回覆強制改成草稿。移除限制只作用於新來訊，不會補發已有草稿或重跑舊作業。

all-private 路線目前只處理新一對一私人文字；群組、廣播、媒體及舊歷史不在範圍。卡片不提供指定測試號碼或切回名單模式的操作，也不因舊名單為空而覆寫目前授權。本人自傳測試另行選擇，不能與客戶收發驗收混算。

首次測試可以只用人工或已確認 FAQ，不需要模型金鑰。要評估 AI 後備，可選本機原生 Codex CLI 或自己的模型 API；只填真實已確認商戶資料、批准有效知識，再另外選擇後備與發送政策。

WhatsApp 與 WhatsApp Business App 沿用同一手機連結流程；Meta Cloud API 是另一種渠道協定，不能把兩者混為一項開發狀態。手機操作參考 [WhatsApp 官方連結裝置說明](https://faq.whatsapp.com/1317564962315842/)；第三方連結裝置服務的實作與限制見 [WHATSAPP_RUNTIME.md](WHATSAPP_RUNTIME.md)，官方手機說明不代表為第三方服務背書。

## 先完成一次人工回覆

1. 管理 →「回覆方式」的回覆處理設定啟用知識庫優先，保持 `automaticKnowledge=false`、`aiFallback=false`、`automaticAi=false`，儲存並讀回。此人工收件匣模式不依賴模型，也不要求代填未知商戶名稱、服務或人工聯絡資料。
2. 核對渠道已連結、webhook 相符及本人已授權的發送範圍。只開收件時，「發送回覆」仍可能不可用；以實際發送 readiness 為準。
3. 在收件匣選同一位客戶，按「開始人工回覆」。此對話轉由人工處理，AI 暫停插入回覆；輸入並核對對客文字後提交。
4. 同一筆訊息在工作台與測試手機核對。排隊／提交／供應商接受不等於送達；以 delivered／read 回執或本人手機確認補足驗收。不明結果先核對，不重按發送。
5. 完成人工處理後，如本人要恢復自動模式，按「交回知識庫」或「交回知識庫／AI」。按鈕名稱隨可用模式而變；同一對話的身份及歷史不變。交接只處理下一則新來訊，不重跑先前訊息。

「AI」、「交回知識庫」及「開始人工回覆」是同一對話的處理模式與操作入口，不是把客戶資料庫搬來搬去。全域回覆政策、模型接駁與單一對話控制分開；模型可用時，人手接管仍優先。上方宿主 Agent 的一般連接狀態亦不能代替客服卡片內的手機／模型／發送狀態。

## 只有自己的 WhatsApp 也可先測回覆

1. 先核對 WhatsApp open 及自身新文字確實出現在「連線測試」。
2. 在管理 →「測試與提示」另開「本人對話回覆測試」，閱讀並同意只測目前帳戶；要試 FAQ，再開啟其獨立自動 FAQ 選項，並確認全域知識庫優先及已確認答案自動回覆已獲批准。
3. 核對知識庫有唯一、已批准且有效的 Hello 完整問題；從手機再傳一則新 Hello。舊訊息不重跑，卡片與手機各自核對真正結果。
4. 在該測試對話用專用人工回覆欄核對並提交。它會暫停該對話的自動 FAQ；要再試自動，明確交回後再傳新 Hello。結果不明先核對手機，不重按發送。

預設只讀、停止條件及驗收界線見 [SELF_REPLY_TEST.md](SELF_REPLY_TEST.md)。這不需要模型，不開放外部顧客發送；斷線、重啟、換帳戶或撤銷後須重新確認。

## 選擇 AI 與助手

「管理 → AI 與助手」保留三個入口：本機登入、模型 API、目前 Codex／DOT 任務。先選需要的路線，詳細限制及說明可按需展開；選擇入口本身不會接駁、執行模型或改變現有回覆政策。

| 本機助手 | 現階段實際狀態 |
| --- | --- |
| Codex | 已有受限 CLI adapter。新版 3101 入口已接入伺服器控制的檢查能力；本人同意並按「檢查並接駁」後，才核對既有 ChatGPT 登入及真正合成推理 |
| Grok | 可選擇閱讀說明或整理指引；尚未接入本機 adapter，未檢查安裝、登入或推理，不能提交接駁 |
| Claude | 可選擇閱讀說明或整理指引；尚未接入本機 adapter，未檢查安裝、登入或推理，不能提交接駁 |

本機助手選單與後台目前正在使用的 adapter 分開。切換選項會要求重新確認同意，不會登出、登入或切換原有接駁；Grok／Claude 不會轉送到 Codex 或付費 API 代試。停用操作仍以後台目前使用的路線為準。

| API 供應商 | 目前可做的事 |
| --- | --- |
| OpenAI | 已有實際 adapter；決定接駁並由本人明確提交後，才測試本人填寫的模型 |
| Anthropic | 可選擇查看狀態；尚未支援，不能提交接駁 |
| Google Gemini | 可選擇查看狀態；尚未支援，不能提交接駁 |
| 其他 | 可選擇查看狀態；尚未支援，不能提交接駁 |

OpenAI 模型可從 `gpt-6-luna`、`gpt-6.1-sol` 參考選單選擇，或改用自訂名稱。這些只是靜態參考，沒有讀取本人帳戶或使用金鑰，也不代表本產品已實測可用；實際可用性須接駁時核對。本機 Codex 使用帳戶預設模型，與這個 API 選單分開。

可以先選供應商及模型，待決定後再處理 API key；未提交金鑰不表示已連線，也不會用另一供應商的 API 代試。日後接駁時只在本機密碼欄安全輸入，不貼到聊天、任務或公開檔案。測試成功與 AI 後備、自動發送仍須各自核對。

需要整理安裝或接駁指引時，「請 AI 整理指引」只在目前 Codex／DOT 任務區填入可編輯草稿；已有未儲存任務時保留原文。本人按「準備任務」才建立任務，另行交接才會請目前 AI 處理。它不會自動新增供應商支援、取得 key、安裝、登入或部署服務。流程示意只幫助閱讀，不是成功狀態；實際狀態以後台讀回為準。

## 接駁原生 Codex 後備

1. 確認這是本人可管理的可信本機，Codex CLI 已由本人登入 ChatGPT，並開啟客服服務。若尚未登入，先由本人完成官方安全登入，再返回本頁檢查；此按鈕不是輸入或搬移登入憑證的入口。不要把登入檔貼入卡片、聊天或 Git；只有安裝人員可以設定可信執行檔位置。
2. 在管理 →「AI 與助手」的本機助手選擇 Codex，明確同意後按「檢查並接駁」。後台核對 CLI 版本、登入及一次真正合成推理，會使用帳戶額度；全部成功才切換 adapter。3101 亦可作這項受限檢查；這個檢查本身不改變 WhatsApp 連結或收發授權，開頁及選擇 Codex 不執行 CLI。可檢查不表示已登入或推理已成功。它沒有喚醒或控制目前左側聊天。
3. 保持 AI 自動發送關閉，啟用 FAQ 優先及 `aiFallback` 並讀回；在單一對話明確交回知識庫／AI。用另一個已授權帳戶送出一則新問題，其措辭不完全命中 FAQ，但已批准知識足以回答；核對草稿的「本機 Codex 背景回覆」標示及實際來源。FAQ 固定答案成功不能代替真正模型驗收。無依據、退款或衝突應轉人工，澄清先存草稿。
4. 真正需要自動發送時，再明確開啟 `automaticAi` 及當前渠道範圍，儲存並讀回；若對話已轉人工，按本人授權交回後再發新問題。到收件手機核對同一筆結果，並核對工作台的模型標示與送達／已讀回執。原生生成最多 25 秒，失敗或逾時轉人工；關閉 fallback 可恢復 FAQ-only／人工。CLI 合成測試不能代替真實渠道驗收。

FAQ 自動答案、AI 後備與 AI 自動發送是不同開關。自傳收件預設只讀；明確開啟獨立「本人對話回覆測試」後，可對新的自身文字測已批准 FAQ 自動回覆及專用人工回覆，仍不建立 CLI、API 或 DOT 工作。詳細配置、原生限制及將來雲端選擇見 [INSTALL.md](INSTALL.md#原生-codex-與選用-api)。

上述第 3、4 步的客戶來訊與手機驗收只適用於具備已授權收發能力的 runtime，不能在只有配置與連線檢查能力的 3101 宣稱完成。CLI 登入檔、原有對話、私人資料與已連結 WhatsApp 均不因選擇或檢查本機助手而重建；重啟後依實際狀態重新同意及檢查。

## 新增知識後會發生甚麼

「新增常見問題」保存完整問題規則及其答案；本人確認且仍有效、唯一完整吻合時才走 FAQ 路線。一般商戶記憶、教學原文及待批准提議不會僅因標題相同而自動成為 FAQ。批准後的普通知識可由已接駁且已啟用的 AI 於新來訊中引用，AI 的回覆仍須通過來源與決策檢查。

儲存知識是一次資料操作，不會主動發 WhatsApp、不重跑舊訊息，也不代表已完成模型理解。要核對新知識，先確定已儲存／批准、對話處於自動模式及回覆政策已讀回，再由測試手機送出新問題。知識與設定更新會使舊版草稿失效；目前 DOT 必須重新讀取最新訊息與 revision，才可保存綁定版本的新草稿。

「從人工對話學習」的自動整理另有同意與開關；產生的建議仍由本人批准。它不因人工發送或開啟 AI 自動回覆就自動生效。日常保存知識與對話不需要 Git commit、重裝客服或重新發行程式。

## 不成功時怎樣處理

| 畫面／現象 | 下一步 |
| --- | --- |
| 未準備服務、沒有 QR | 先啟動接駁服務並核對私人設定；保留未連接狀態 |
| 一般 QR 過期或手機仍 connecting | 檢查最新有效 QR 及當前連線狀態；只有仍需掃碼時才請本人再連結 |
| 401／logged_out／登入授權失效 | 停止反覆掃碼；由安裝人員核對安全原因及同帳戶綁定，必要時走保留舊資料的重新配對流程。不能猜測供應商根因或直接刪 auth |
| 手機已連結，卡片沒有來訊 | 讀回本人已確認的 all-private 收件、webhook 與 callback；用授權範圍內另一帳號的新文字核對，毋須測試名單 |
| 已收到來訊，但人工回覆不可用 | 核對知識庫優先的人工模式、獨立渠道發送授權及「開始人工回覆」狀態；不要為通過舊模式條件填虛構商戶資料 |
| 「交回知識庫／AI」不可用或沒有模型回覆 | 分開核對知識庫優先、真正模型推理、aiFallback、單一對話是否仍由人工接手；更改後用新來訊驗證 |
| 新增知識後沒有即時訊息 | 核對是否已確認、屬 FAQ 還是一般記憶、是否有新來訊及相應發送政策；儲存知識本身不發訊、不重跑舊問題 |
| AI 已產生澄清但沒有發送 | clarify 一律先存草稿；資料不足、退款、無來源或窗口逾時交人工，不應誤判為渠道故障 |
| 只見 accepted 或 uncertain | 到收件手機及供應商核對；未有送達證據不宣稱已收到，不自動重發 |
| 宿主只顯示卡片，操作無法保存 | 宿主仍缺 renderer／受限 API；先補該能力，不覆蓋工作室其他頁面 |

## 網頁渠道及離線示範

「接駁網頁」是可選的另一條客人渠道。開啟後可取得 `/chat` 網址，僅提供受限會話，不公開管理員工具；localhost 只限同機。其收件成功不代表 WhatsApp 手機收件。

離線規則只示範已確認文字的固定分類問答，不能當作完整 AI 效果。`/diagnostics/console` 是獨立診斷工具，不是客服 Agent 的正式介面。

閱讀完「完成教學」不會改變手機連線、收件／回覆同意或驗收狀態。原生 Codex／DOT 交接仍由本人確認；安裝指引任務只保存草稿，不自行部署私人工作室。

重啟／更新後先核對真正服務、模型與程序內發送授權，再依本人既有授權恢復同一範圍；不要由舊成功摘要推斷目前狀態。工程問題按 [統一回饋流程](FEEDBACK_LOOP.md) 記錄到同一案例，更新同一客服實例用 [UPDATE_AI.txt](../UPDATE_AI.txt)。真實訊息、手機資料與驗收截圖留在私人儲存，不加入公開案例。

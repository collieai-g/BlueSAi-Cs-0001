# 從人工對話建立商戶知識與處理流程

客服仍是工作室 Agent 工作台的一張卡片；以下功能位於該卡片的「知識庫」，不更改宿主總覽、工作、資料或導覽。

## 回覆與學習是兩條工作

已確認 FAQ 先作唯一完整比對；未命中時，只有已啟用 AI 後備且模型真正接駁，才按相關已確認知識理解不同問法。模型回覆須附有效事實來源；不能把相似字眼本身當成答案證據。必要資料不足時先產生一個追問草稿，保留本人核對，不會猜到貨日期或聲稱已查訂單。

商戶預先在 FAQ 設定問題及答案，或在「教客服」描述功能與處理方法。接駁模型後，教學入口可整理原文；離線保存仍清楚標為待確認，不能視作模型已理解。使用原生 Codex 或自己的模型 API，均使用同一來源及批准界線。

人工對話學習流程：

`人工回覆成功提交 → 收錄學習紀錄 → AI 提出待確認記憶 → 本人編輯／批准 → 下次回覆檢索`

只有一般 WhatsApp／網頁客戶對話中已 accepted／delivered／read 的 staff 文字可建立學習紀錄。排隊、失敗、不明結果、AI 草稿、離線示範及本人自傳測試不作人工示範。accepted 只代表供應商接受，不宣稱客戶已收到。既有人工文字保留在原對話；學習紀錄與提議不複製成已批准知識。

## 三種記憶

| 類型 | 可整理內容 | 使用界線 |
| --- | --- | --- |
| 商戶事實 | 本人確認的功能、服務、價格及政策 | 回答商戶事實時必須引用有效來源 |
| 處理流程 | 何時適用、缺少甚麼先問、處理次序、例外與交人工條件 | 指導理解與追問；流程不能證明價格、到貨日期或物流結果 |
| 回覆風格 | 語氣、長度、每次問幾個問題 | 不作商戶事實來源 |

客戶姓名、電話、地址、訂單識別及當次物流狀態不能變成全店知識。模型收到的是有限、保留 user／staff／assistant 角色及來源的去識別材料；先前 AI 文字與客戶說法不能授權公司政策。提議引用實際人工示範，列明待補問題與可能衝突。無足夠依據可以不提議。

例如「貨品幾時到？」及人工回覆「你想了解哪件貨品？」可支持候選流程「查到貨時間前先識別貨品」。它不能支持「三天送到」、新配送政策或已查物流；未有資訊的後續步驟只列為待本人補充。

## 卡片操作

1. 在知識庫預先建立及確認 FAQ／商戶資料。
2. 完成原生 Codex 或模型 API 的真正推理檢查，並按需要啟用 AI 後備處理不同問法。手機連線與模型連線分開核對。
3. 人工對話成功提交後，更新「從人工對話學習」紀錄；可逐筆要求 AI 整理，或另行同意自動整理。
4. 閱讀提議的類型、原對話依據、適用條件、待補問題及衝突。編輯後明確確認；來源已變動時重新分析。
5. 批准才加入正式知識；不採用的建議保留審閱狀態。正式批准、編輯及撤銷仍會使舊版本回覆失效。

未連模型時可以保存及整理紀錄，但不假稱已完成 AI 分析。自動整理預設關閉，開啟只產生待確認提議，不批准知識、不開啟 AI 發送、不把人工作法自動套用到全部客戶。人工接手的對話仍由本人控制。

## 執行與資料

schema 7 附加 learning_cases 與 learning_proposals，保留原商戶、FAQ、對話、批准及回執。每則成功人工來源只收錄一次；角色、來源雜湊與有界快照可核對。候選建立及背景分析不增加正式知識 revision，避免取消正在排隊的人工回覆。正式批准才增加 revision。

本版最多保留 200 筆學習紀錄，畫面列出最近 100 筆紀錄與 100 條提議。達上限後仍保存原客戶對話，暫停新增學習紀錄並顯示容量提示；本版未提供學習紀錄封存或清除介面。

背景整理與渠道發送分開執行，停止或更換模型後不採用舊結果。分析失敗保留固定錯誤碼及可重試紀錄，不保存模型原始 stderr 或秘密。模型上下文及知識數量有界，不聲稱讀取手機舊歷史或永久修改 OpenAI 模型本身。

即時原生回覆維持 25 秒推理期限。商戶教學及人工對話整理為獨立背景工作，模型最多 60 秒，服務連同清理與回存最多等候 65 秒；這不延長客戶回覆窗口，也不阻塞人工發送。達期限保留原對話及失敗紀錄，不自動反覆重試。

卡片 API 全部位於 `/api/agents/bluesai-cs-0001`：

- GET／PUT `/knowledge-learning`：狀態及明確自動整理設定。
- POST `/knowledge-learning/collect`：收錄已送人工紀錄。
- POST `/knowledge-learning/cases/:id/analyze`：排隊分析；202 不代表已完成。
- POST `/knowledge-learning/proposals/:id/approve`：本人確認後採用；有待補問題或衝突須另行確認已核對。
- POST `/knowledge-learning/proposals/:id/reject`：保留不採用決定。

## 接入 02 測試工作室之前

先完成本機功能驗證、固定完整來源 commit 及產生不含私人資料的版本套件，再按 [INSTALL_PACKAGE.md](INSTALL_PACKAGE.md) 對實際工作室做只讀 preflight。卡片 renderer、受限 API 及外部後台持續性都要符合宿主合約；不能把 localhost、source.tar 或 GitHub PR 當作工作室已部署。本機 SQLite／手機 auth 留在私人執行環境，不能放入公開套件或覆蓋宿主資料。

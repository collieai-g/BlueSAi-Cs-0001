# 客服 Agent 卡片介面

版本：0.4.0-preview.1，交互修訂：2026-10-26。此文件取代早期把整套客服管理後台當成 Agent 入口，以及把對話藏在基本設定內的呈現方式。

## 固定介面邊界

正式入口為「AI → Agent 工作台 → BlueSAI 客服」。客服只是一個已登記的 Agent 卡片項目，精簡入口與展開工作區是同一實例的狀態。整體限制見 [AGENT_UI_CONTRACT.md](AGENT_UI_CONTRACT.md)。

卡片不渲染工作室的側欄、頂列、公司切換或「總覽／工作／AI／資料」主導覽，也不提供能替換宿主這些頁面的安裝包。宿主負責外層導覽、身份、主題及排版；客服只管理自己的根節點及資料。

主要檢視改為「收件匣／知識庫／管理」，展開預設進入收件匣。舊 basic／training／connect 可保留作內部事件及資料相容，不代表使用者仍須沿用舊導覽。客戶來訊、核對、人工接手及回覆留在卡片自己的內容區，不要求使用者離開 Agent 進入另一套客服總覽網站。

## 入口與日常工作區

入口顯示客服名稱、Agent 編號、實際 WhatsApp 狀態與待本人處理數量，主要操作是「開啟收件匣」。管理及 WhatsApp 接駁保留為次要捷徑；不把全部設定表單放在入口。返回入口、切換檢視及展開上下文仍使用同一個 Agent／instance，保留選定對話與各客戶未送出的文字。

| 檢視 | 主要內容 |
| --- | --- |
| 收件匣 | 對話列表、所選訊息、草稿及人工回覆；上下文顯示真實處理狀態、有效知識來源與發送條件 |
| 知識庫 | 已核對 FAQ、待確認／已批准／失效記憶、教學輸入及修改／批准操作 |
| 管理 | 商戶資料、回覆政策與自動發送確認、渠道狀態中心、WhatsApp／網頁教學、選用模型與一般 DOT 任務 |

列表顯示真實渠道、名稱、最近訊息、時間與處理狀態。待處理數不是未讀數；自傳測試不計入客戶待處理。篩選只反映已存在的狀態，搜尋範圍是目前載入的對話，沒有全手機歷史搜尋。未實作的 CRM 屬性、工單結案、分派、SLA 或退款執行不加入可操作控件。

訊息由舊到新排列。草稿與已提交訊息清楚分開，回覆欄綁定目前客戶；新訊息或切換對話不能令未送出內容落到另一位客戶。人工回覆先接手，交回知識庫或 AI 是另外的明確動作。DOT 只讀取所選客戶最新上下文並保存版本綁定草稿；開啟原生編輯器不表示已閱讀，保存草稿不表示已發送。

已批准 FAQ 只有唯一完整問題吻合且仍有效時才直接採用。全域知識庫優先與自動發送政策放在管理；不能在處理單一對話時無意切換所有客戶的自動回覆。普通筆記不會自動成為完整問題規則。

## 舊介面為何要改

| 舊做法及問題 | 新做法及操作目的 |
| --- | --- |
| 用下拉選單選客戶，新對話及待處理情況不易察覺 | 可見對話隊列顯示最近訊息、時間、渠道及真實處理狀態；直接選取客戶，篩選待本人處理 |
| 約 180px 訊息區與商戶表單、全域政策混在基本設定 | 收件匣以對話及回覆為中心；全域政策和長表單移到管理，知識維護移到知識庫 |
| 已正常接駁的使用者仍被送回四步教學起點 | 管理先顯示渠道狀態中心；正常時可檢查或調整，缺項時提供一個對應下一步，QR 及完整教學按需開啟 |
| 自傳連線測試與真正客戶來訊混在一起 | 連線測試另列篩選及只讀標記，不計入客戶待處理，不提供發送或 DOT 操作 |
| 用整體「已連接」概括對話處理及發送 | 渠道狀態、草稿、已提交、accepted、delivered／read 分開呈現；未知結果提示核對手機，沒有假 CRM 或完成狀態 |

這次改動改變工作次序與資訊位置，並非只把舊三個分頁改名。對話列表負責找到工作，時間線負責理解及回覆，上下文負責核對來源與條件；管理只在設定或修正缺項時打開。

## 一次處理流程

1. 從入口開啟收件匣，先看待本人處理的客戶。未有來訊時顯示實際缺項；未接駁便引導到管理，已接駁則提示由另一個已授權帳戶傳新文字。
2. 選擇一位客戶，閱讀最新訊息及上下文。核對知識來源、目前是知識庫／AI 或人工處理，以及渠道是否允許回覆；不因開啟對話就自動接手或發送。
3. 有可用答案時核對草稿；需要協助時明確交給 DOT 讀取目前對話，結果只保存為待確認草稿。客戶或知識變更後重新閱讀，不沿用過期版本。
4. 本人先接手再編寫人工回覆，或批准符合條件的客服草稿。送出後在同一時間線核對真正結果；accepted 不等於送達，uncertain 不直接重發。
5. 若要重用一個已核實答案，到知識庫另建／批准完整 FAQ；若要改所有客戶的處理政策，到管理明確確認。單次人工回覆不會自動變成共用知識或自動發送授權。

自傳訊息只走獨立的連線測試閱讀流程，不能走上述對客回覆步驟。卡片提示本人／瀏覽器通知、原生 DOT 編輯器開啟、DOT 已保存草稿及真正客戶收件，均按各自證據顯示。

## 空間與上下文

864 CSS px 預設卡片使用列表＋對話雙欄，上下文按需開啟抽屜；可用內容寬達 1080 CSS px 才可呈現列表／對話／上下文三欄。欄位數按卡片實際可用寬度判斷，不按整個螢幕寬度硬塞。抽屜提供關閉按鈕、鍵盤操作及焦點返回，不改變對話選取。

手機及不足以維持雙欄的卡片只顯示列表或所選詳情，透過返回列表切換；上下文另以抽屜開啟。320px 不水平捲動、不縮細文字。訊息閱讀位置與各客戶輸入保留；正在閱讀較早內容時，新訊息不強制跳到最底。

目前後台只提供最近最多 200 段已保存對話；搜尋及篩選在這批已載入資料進行，不能當作全資料庫或手機歷史搜尋。這避免為本次介面重排加入未實作的全庫搜尋；需要更早內容時先另行提供真正分頁與搜尋接口。864px 採上下文抽屜是保留訊息及回覆寬度的取捨，不以增加宿主卡片上限或強迫全螢幕解決。

## 操作與真實狀態

- 「接駁 WhatsApp」為本次主要流程：檢查服務、取得真正 QR、本人手機掃碼、核對收件及指定號碼試覆。
- WhatsApp 手機狀態與 AI 模型狀態分開顯示；沒有模型金鑰不代表手機不能連結或人工回覆不能測試。
- 卡片就緒、服務設定齊全、手機 open、來訊已保存、provider accepted、手機送達是不同觀察結果。
- 不能用離線答案或網頁扮演客人的成功畫面宣稱 WhatsApp 已測試。
- 缺少能力時，畫面說明缺少什麼、目前能做什麼，以及下一個可執行步驟；不使用一個籠統的「已連接」覆蓋所有狀態。
- 「自己傳自己」放在連線測試檢視並持續標示只讀；不進入客戶待處理、知識庫回答、DOT 草稿或人工發送流程，不當成客戶雙向驗收。

## 表單與閱讀

空白商戶欄位保持空白。訓練原文預設待確認；批准、撤銷及失效維持後台控制。切換檢視、查看對話及背景狀態更新保留未儲存輸入。按鍵寫出實際操作結果。管理表單與渠道教學不佔用日常訊息時間線。

本機卡片的來源是 `design/customer-agent-card-design.html`，由 `tools/build-workbench.py` 產生 `public/workbench.*`；不可只改產出檔案。HTTP client 放 `public/workbench-api.js`，只呼叫 `/api/agents/bluesai-cs-0001`。

卡片尺寸、24px 宿主方格、窄畫布閱讀模式、320px 與 200% zoom 驗收依 [BLUEPRINT_PLUGIN_DESIGN.md](BLUEPRINT_PLUGIN_DESIGN.md)。未完成的宿主拖移／縮放整合不得寫成可用。

## 共用資產及舊介面

共用 Blueprint 資產固定於 `UI_SOURCE.json` 記錄的 commit，MIT 聲明及雜湊保留。不能直接修改 `public/vendor/` 來影響整個宿主；卡片樣式只作用於客服根節點。

早期 `public/index.html`／`public/app.js` 的整頁工具保留作獨立診斷，僅在 `/diagnostics/console` 明確使用。它不是正式 Agent UI，不能搬進工作室或替換宿主的任何主列。歷史截圖及驗證記錄只證明當時版本，不能代證本版卡片或真實手機測試。

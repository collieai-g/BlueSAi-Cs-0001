# 客服 Agent 卡片介面

版本：0.4.0-preview.2，交互修訂：2026-10-28。此文件取代早期把整套客服管理後台當成 Agent 入口，以及把對話藏在基本設定內的呈現方式。

## 固定介面邊界

正式入口為「AI → Agent 工作台 → BlueSAI 客服」。客服只是一個已登記的 Agent 卡片項目，精簡入口與展開工作區是同一實例的狀態。整體限制見 [AGENT_UI_CONTRACT.md](AGENT_UI_CONTRACT.md)。

卡片不渲染工作室的側欄、頂列、公司切換或「總覽／工作／AI／資料」主導覽，也不提供能替換宿主這些頁面的安裝包。宿主負責外層導覽、身份、主題及排版；客服只管理自己的根節點及資料。

主要檢視改為「收件匣／知識庫／管理」，展開預設進入收件匣。舊 basic／training／connect 可保留作內部事件及資料相容，不代表使用者仍須沿用舊導覽。客戶來訊、核對、人工接手及回覆留在卡片自己的內容區，不要求使用者離開 Agent 進入另一套客服總覽網站。

## 入口與日常工作區

入口顯示客服名稱、Agent 編號、實際 WhatsApp 狀態與待本人處理數量，主要操作是「開啟收件匣」。管理及 WhatsApp 接駁保留為次要捷徑；不把全部設定表單放在入口。返回入口、切換檢視及展開上下文仍使用同一個 Agent／instance，保留選定對話與各客戶未送出的文字。

| 檢視 | 主要內容 |
| --- | --- |
| 收件匣 | 對話列表、所選訊息、草稿及人工回覆；上下文顯示真實處理狀態、有效知識來源與發送條件 |
| 知識庫 | 已核對 FAQ、待確認／已批准／失效記憶、教學輸入及修改／批准操作 |
| 管理 | 商戶資料、FAQ／AI 後備與各自自動發送確認、渠道狀態中心、WhatsApp／網頁教學、原生 CLI／選用 API 與一般 DOT 任務 |

收件匣列表保留「全部客戶／待處理」兩個篩選，移除列表更新按鈕及「人工接手／連線測試」篩選的專用計數與路徑。客戶列表不包含本人自傳測試，原測試紀錄仍留在後台。來訊透過 SSE 與既有輪詢自動讀回；頁尾顯示最後成功更新時間，採 `HH:mm` 24 小時制（例如 `21:54`），不以持續走動的時鐘冒充同步成功。對話內人工接手及交回知識庫／AI 的控制繼續使用。

詳情分為「對話資料／目前處理／最近回覆／本次回覆依據」。依既有資料顯示渠道、最近來訊、已載入記錄數、處理狀態與原因、目前政策及發送條件；最近回覆標示實際方式、發送狀態及建立時間，不把建立時間當成送達時間。引用知識採來源卡片並保留 revision／草稿有效性核對；切換對話或尚未選取時清除前一位客戶的詳情。桌面與窄屏沿用同一詳情抽屜，不新增分派、SLA 或虛構客戶欄位。

## 管理的分區工作面

管理在同一張 4:3 卡片內以左側分類與右側內容工作面呈現。分類寬度隨卡片調整至 144–208 CSS px，分類名稱及副文字持續可見；右側在固定位置顯示所選內容。縮小時維持左右位置及各自捲動，不轉成上方分類列；分類不取代工作室主導覽。

| 分類 | 保留的內容及控制 |
| --- | --- |
| 渠道接駁 | 已連結電話、手機連線燈及實際收件範圍；WhatsApp 一鍵手機連結；成功後按能力展開收件／回覆設定；可選網頁渠道 |
| 回覆方式 | 知識庫優先、已確認 FAQ 自動回覆、AI 後備與 AI 自動發送，各自的確認及儲存操作 |
| AI 與助手 | 本機登入、模型 API、目前 Codex／DOT 任務三個入口；本機 Codex／Grok／Claude 與 API 供應商各自顯示真實支援狀態 |
| 商戶資料 | 原有完整商戶表單及儲存操作；未知欄位保持空白 |
| 測試與提示 | 本人對話回覆測試、獨立 FAQ 測試同意及瀏覽器待處理提示 |

預設分類為「渠道接駁」。WhatsApp 總覽顯示後台已核對的連結電話、手機連線燈及實際收件範圍；不堆放回覆授權、下一步、檢查收件或本人測試驗收摘要。手機已連接用綠燈，未連接用紅燈，狀態未能確認時清楚標示待核對；紅／綠燈以緩慢的明暗變化提示，偏好減少動態時停用動畫。電話只從當前已連結帳戶的受限狀態取得；未提供或已斷線時不顯示舊電話，不以 instance 名稱、登入 ID 或示例電話補造。

連線燈只表示手機連結，不能概括收件、發送、模型或客戶送達。3101 本機工作台在手機接駁後自動準備新私人文字收件；只有帳戶、入口及範圍均已核對才顯示接收中，並在準備或失敗時顯示實際狀態與重試。此模式不顯示獨立收件表單；新來訊按已保存的知識庫／AI 自動回覆政策處理，人工接手時由本人回覆。其他 runtime 沿用其原有範圍設定。網頁渠道仍可見，標明為可選；商戶及模型表單、全域政策、本人測試、通知與一般 DOT 任務仍在各自分類內使用。

WhatsApp 主按鈕啟動單一連結工作面：準備服務、顯示真實 QR、等待手機確認、核對已接駁。畫面只呈現目前階段，不要求使用者逐一按「下一步」或先手填技術設定。本人按鍵後，本機準備能力才可檢查固定入口與已安裝依賴，啟動使用獨立 Git 外資料的專用 bridge；按鍵不下載或安裝套件，缺少依賴或能力時明列缺項。主流程不跳到頁底的一般任務表單，進階配置及安裝協助按需展開。

本機 bridge 啟動就緒確認最多等待十五秒，後續檢查及清理另有限時；頁面準備等候最多十分鐘，連線輪詢最多三分鐘。成功必須來自後台的 `open` 及有效核對時間；取消、逾時或錯誤會停止本頁等待並移除 QR，提供重試，不能推斷手機已連結或服務已停止。取消不停止已開始的後台準備、不解除手機授權或刪除 auth。開頁與分類切換不自動開始連線，也不因重新整理重建另一套資料。

3101 配置預覽提供獨立 bridge、手機連結及本機自動收件，並可按已啟用政策自動回覆最近來訊；受限 Codex 檢查與收件分開。手機成功面只表示手機已接駁，Codex 推理成功不代表真正收到或送達客戶訊息；真實收發仍須另行驗收。

分類與步驟切換不重建表單節點，不清空商戶資料、模型設定、同意選項或尚未送出的任務文字；切換本身不提交表單。鍵盤焦點及目前分類要可辨識，背景狀態更新仍不能搶走正在編輯的焦點。既有後台 API、批准、人工接手及資料保留語意繼續適用。

## AI 與助手的三個入口

本頁以「本機登入／模型 API／目前 Codex・DOT 任務」三個入口說明選擇，先顯示短說明、實際狀態與主要操作；額度、限制及進階說明按需展開。本機 Codex 的本人同意及真正檢查、API 的模型與密碼欄、一般任務及已保存草稿仍使用原有控制。裝飾性的流程示意須明示為示意，遵守減少動態偏好，不能冒充連線、推理或任務完成狀態。

本機登入選單保留 Codex、Grok、Claude 三個候選，只有 Codex 已接入受限 adapter。選擇 Grok／Claude 時顯示「尚未提供本機接駁，未檢查安裝或登入」，停用同意與提交，只保留閱讀說明及整理指引；不以選單存在宣稱已實作，也不把其操作轉送到 Codex 或 API。候選選項與目前已連接 provider 分開呈現；改選會清除本次同意，不能令目前 Codex 連接被誤標為 Grok／Claude，停用仍作用於目前實際 adapter。

新版 3101 入口由伺服器明確提供 Codex preview 能力，沿用同一受限 CLI adapter、可信執行檔及該預覽 Git 外工作目錄，不將 preview 改為收發 runtime。`nativeAvailable` 為真時才開放同意及「檢查並接駁」；它只表示可進行檢查，開頁不檢查登入，選中 Codex 不執行 CLI。本人同意並提交後才核對版本、既有 ChatGPT 登入及合成推理；失敗保留原連接與政策，成功亦不自動啟用回覆或發送。

模型 API 提供 OpenAI、Anthropic、Google Gemini 及其他供應商選擇；目前只有 OpenAI adapter 已實作。選擇其餘項目時顯示尚未支援並阻止提交，不把其他供應商的金鑰送往 OpenAI。OpenAI 模型可選 `gpt-6-luna`、`gpt-6.1-sol` 參考項目或自訂名稱；這是靜態參考，不是已讀取帳戶的模型清單，也不代表本產品已實測該模型，實際可用性仍須日後接駁時核對。

選供應商、輸入模型、開頁或切換區域都不發出接駁請求，也不改現有 adapter、回覆政策或未儲存草稿。決定使用支援的 API 後，只有本人明確提交才可測試真正模型；未提供或未提交金鑰時保留未接駁狀態，不代填金鑰或製造成功。連接成功仍不開啟 AI 後備及自動發送，須到「回覆方式」另行確認。

「請 AI 整理指引」只填入可編輯的現有 Codex／DOT 任務草稿；已有未儲存任務則保留，不自行保存任務或呼叫 AI。本人另按「準備任務」及明確交接後才處理，不會自動安裝 adapter、取得 API key、登入或接駁。本機原生 CLI 與目前左側聊天繼續分開，使用帳戶預設模型，不套用 API 模型選單；未有本機執行器的環境明示不可用，不能由展示入口推斷已可推理。

## 收件匣與回覆

列表顯示真實渠道、名稱、最近訊息、時間與處理狀態。待處理數不是未讀數；自傳測試不計入客戶待處理。篩選只反映已存在的狀態，搜尋範圍是目前載入的對話，沒有全手機歷史搜尋。未實作的 CRM 屬性、工單結案、分派、SLA 或退款執行不加入可操作控件。

訊息由舊到新排列。草稿與已提交訊息清楚分開，回覆欄綁定目前客戶；新訊息或切換對話不能令未送出內容落到另一位客戶。人工回覆先接手，交回知識庫或 AI 是另外的明確動作。DOT 只讀取所選客戶最新上下文並保存版本綁定草稿；開啟原生編輯器不表示已閱讀，保存草稿不表示已發送。

已批准 FAQ 只有唯一完整問題吻合且仍有效時才直接採用。全域知識庫優先與自動發送政策放在管理；不能在處理單一對話時無意切換所有客戶的自動回覆。普通筆記不會自動成為完整問題規則。

FAQ-only、原生 Codex CLI 與模型 API 分開標示。原生接駁須本人同意真正合成測試，成功只切換 adapter，不改政策；說明使用 ChatGPT 帳戶額度、不是控制目前左側聊天。`aiFallback` 預設關閉、需 FAQ 優先及可用 adapter；`automaticAi` 預設關閉、需先有 fallback。FAQ 自動答案的 `automaticKnowledge` 保留獨立。模型推理與渠道送達狀態各自顯示，測試失敗提供固定原因及回到 FAQ／人工的操作。

## 舊介面為何要改

| 舊做法及問題 | 新做法及操作目的 |
| --- | --- |
| 用下拉選單選客戶，新對話及待處理情況不易察覺 | 可見對話隊列顯示最近訊息、時間、渠道及真實處理狀態；直接選取客戶，篩選待本人處理 |
| 約 180px 訊息區與商戶表單、全域政策混在基本設定 | 收件匣以對話及回覆為中心；全域政策和長表單移到管理，知識維護移到知識庫 |
| 已正常接駁的使用者仍被送回四步教學起點 | 管理先顯示電話與手機連線燈；一次按鍵核對並完成手機連結，進階及收件設定按需展開 |
| 自傳連線測試與真正客戶來訊混在一起 | 連線測試另列，預設只讀；明確開啟本人回覆測試後才提供獨立 FAQ／人工操作，仍不計入客戶待處理或提供 DOT |
| 用整體「已連接」概括對話處理及發送 | 渠道狀態、草稿、已提交、accepted、delivered／read 分開呈現；未知結果提示核對手機，沒有假 CRM 或完成狀態 |

這次改動改變工作次序與資訊位置，並非只把舊三個分頁改名。對話列表負責找到工作，時間線負責理解及回覆，上下文負責核對來源與條件；管理只在設定或修正缺項時打開。

## 一次處理流程

1. 從入口開啟收件匣，先看待本人處理的客戶。未有來訊時顯示實際缺項；未接駁便引導到管理，已接駁則提示由另一個已授權帳戶傳新文字。
2. 選擇一位客戶，閱讀最新訊息及上下文。核對知識來源、目前是知識庫／AI 或人工處理，以及渠道是否允許回覆；不因開啟對話就自動接手或發送。
3. 有可用答案時核對草稿；需要協助時明確交給 DOT 讀取目前對話，結果只保存為待確認草稿。客戶或知識變更後重新閱讀，不沿用過期版本。
4. 本人先接手再編寫人工回覆，或批准符合條件的客服草稿。送出後在同一時間線核對真正結果；accepted 不等於送達，uncertain 不直接重發。
5. 若要重用一個已核實答案，到知識庫另建／批准完整 FAQ；若要改所有客戶的處理政策，到管理明確確認。單次人工回覆不會自動變成共用知識或自動發送授權。

自傳訊息預設走獨立只讀流程；另行明確開啟「本人對話回覆測試」後，使用其專用 FAQ／人工操作，不能套用上述對客回覆授權。人工提交切至 self_human；交回 self_auto 後須手機再傳新訊息，舊 Hello 不自動重跑。卡片提示本人／瀏覽器通知、原生 DOT 編輯器開啟、DOT 已保存草稿及真正客戶收件，均按各自證據顯示。

## 空間與上下文

展開主卡片使用固定 4:3 外框，包含頂列、分頁、內容及頁尾；最小 576×432、標準 864×648、最大 1152×864 CSS px，中型 768×576。收件匣、知識庫及管理共用同一外框，首頁精簡入口沿用現有設計。宿主依 24px 方格以 96×72px 成對步階調整；客服主卡片比例與宿主額外控制列高度分開核對。

收件匣永遠保持左右雙欄。左側對話／客戶諮詢區寬度為 `clamp(176px,28%,288px)`，右側使用餘下空間；客戶清單及訊息區分別垂直捲動，回覆欄固定在右側底部。詳情沿用卡片內抽屜，提供關閉、鍵盤操作及焦點返回，不變更對話選取。長篇處理說明收納於現有詳情，保留原內容。

管理左側分類寬度為 `clamp(144px,20%,208px)`，右側設定使用餘下空間。兩區一直維持左右位置，分類名稱及副文字保留；分類及設定內容各自在同一外框捲動。

畫面不足 576px 時，客服根節點提供水平捲動，保留最小 576×432 主卡片。取消隱藏左側或右側的手機切換模式，不搬動管理分類到上方，不用縮細文字換取空間。訊息閱讀位置與各客戶輸入保留；正在閱讀較早內容時，新訊息不強制跳到最底。

目前後台只提供最近最多 200 段已保存對話；搜尋及篩選在這批已載入資料進行，不能當作全資料庫或手機歷史搜尋。這避免為本次介面重排加入未實作的全庫搜尋；需要更早內容時先另行提供真正分頁與搜尋接口。詳情抽屜保留訊息及回覆的主要寬度，不增加宿主卡片上限或強迫全螢幕。

## 操作與真實狀態

- 「接駁 WhatsApp」為本次主要流程：檢查服務、取得真正 QR、本人手機掃碼，本機自動準備新私人文字收件，再以另一個已授權帳戶試收試覆；毋須登記測試號碼。
- WhatsApp 手機狀態與 AI 模型狀態分開顯示；沒有模型金鑰不代表手機不能連結或人工回覆不能測試。
- 卡片就緒、服務設定齊全、手機 open、來訊已保存、provider accepted、手機送達是不同觀察結果。
- 不能用離線答案或網頁扮演客人的成功畫面宣稱 WhatsApp 已測試。
- 缺少能力時，畫面說明缺少什麼、目前能做什麼，以及下一個可執行步驟；不使用一個籠統的「已連接」覆蓋所有狀態。
- 「自己傳自己」放在連線測試檢視，明示預設只讀及目前授權。另設「本人對話回覆測試」與獨立自動 FAQ 選項；未有全域知識庫優先／已確認 FAQ 自動授權時，說明只可人工或先明確開啟相應政策；只允許新自身文字的已批准 FAQ／專用人工回覆，不進入 CLI／API／DOT、客戶待處理或通知。顯示 self_human／self_auto、需新來訊與停止原因；uncertain 不提供直接重送。重啟、斷線、換帳戶或撤銷後關閉；不當成客戶雙向驗收。[操作合約](SELF_REPLY_TEST.md)

## 表單與閱讀

入口沿用同一客服身份、管理入口、渠道燈、開啟收件匣按鍵與原有配色。展開工作區採精簡比例：桌面內文及訊息 13px、區段標題 15–16px、一般控制最小高度 32px，縮減表單、訊息框和段落留白；觸控環境保留最小 40px 操作及 16px 輸入文字。不以 CSS zoom、transform 或瀏覽器縮放改變整張卡片。

三個主要檢視以主卡片實際寬高分配內容，不再依瀏覽器高度計算工作區；頂列、分頁及頁尾外的剩餘空間由內容填滿。訊息區、知識內容及管理內容各在自己的工作面捲動，回覆欄保持在右側底部。最小尺寸先縮減留白及重新排列按鈕；核心工作區、既有詳情及可恢復草稿保留。

空白商戶欄位保持空白。訓練原文預設待確認；批准、撤銷及失效維持後台控制。切換檢視、查看對話及背景狀態更新保留未儲存輸入。按鍵寫出實際操作結果。管理表單與渠道教學不佔用日常訊息時間線。

本機卡片的來源是 `design/customer-agent-card-design.html`，由 `tools/build-workbench.py` 產生 `public/workbench.*`；不可只改產出檔案。HTTP client 放 `public/workbench-api.js`，只呼叫 `/api/agents/bluesai-cs-0001`。

卡片尺寸、24px 宿主方格、窄畫布閱讀模式、320px 與 200% zoom 驗收依 [BLUEPRINT_PLUGIN_DESIGN.md](BLUEPRINT_PLUGIN_DESIGN.md)。未完成的宿主拖移／縮放整合不得寫成可用。

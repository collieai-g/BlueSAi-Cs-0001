# 藍圖工作室內置客服插件：介面與卡片規格

設計基準：0.4.0-preview.1，交互修訂：2026-10-26。項目：BlueSAI-客服；Agent：`BlueSAi-Cs-#0001`。

本文件的介面與資料禁止事項以 [AGENT_UI_CONTRACT.md](AGENT_UI_CONTRACT.md) 為固定合約；舊整頁管理畫面只作歷史診斷，不是 Agent UI。

## 產品定位與目前交付

**BlueSAI-客服是專門為 Blueprint Studio（藍圖工作室）設計的內置客服 AI 插件。** 正式產品入口是「AI → Agent 工作台 → 客服 AI 卡片」。商戶在同一個工作室內設定客服、訓練記憶及接駁渠道，介面設計和操作規則遵循工作室的原生設計。

本機入口只呈現客服卡片，不包含工作室側欄、頂列或主導覽。`npm start` 的 `/` 與 `/workbench.html` 使用真正客服執行器；`npm run workbench` 的 3101 只作隔離卡片預覽。正式嵌入時宿主提供外層介面，客服只掛載自己的根節點及 `/api/agents/bluesai-cs-0001` 受限接口。

**「專為工作室設計」是產品定位；「已安裝進工作室」是部署狀態。** 目前尚未把插件註冊到測試工作室，也未接入其原生排版引擎。`agent.json` 是項目身份與定位資料，並非工作室可直接安裝的插件格式。本文件的移動、縮放及尺寸上限是後續整合必須遵守的規格，不代表本機版本已實作。

## 原生設計來源

沿用工作室的品牌、字體、色彩、按鈕、欄位、焦點樣式、間距、圓角及導覽層級。正式嵌入時優先重用宿主元件及樣式；不要另外製作一套相似但行為不同的工作室。

本次核對 [Blueprint Studio workspace.js](https://github.com/collieai-g/Blueprint-Studio-Open-Source/blob/d23d271f60cb32b208960e62fe03f771de5a2b8b/library_web/workspace.js) 及 [原生卡片樣式](https://github.com/collieai-g/Blueprint-Studio-Open-Source/blob/d23d271f60cb32b208960e62fe03f771de5a2b8b/library_web/style.css)：

- 總覽排版以 **24 CSS px 為一格**；一頁 48 行，最多三頁。
- 調整排版時可用把手拖動、調整大小，亦可用方向鍵按格操作。
- 排版會處理邊界和卡片碰撞；放不下的操作會被拒絕，不刪除或隱藏其他卡片。
- 窄螢幕使用另一個閱讀排列，保留原有桌面位置及尺寸；排版偏好與商戶資料分開。

這是已核對的「總覽卡片」行為。現有程式有固定卡片 ID 清單，不能假設放入客服 HTML 就會自動支援。把同一套能力帶到 Agent 工作台，需要宿主擴充卡片註冊及每類卡片的尺寸限制；本次沒有修改宿主倉庫或其測試環境。

已複製的共用視覺資產仍固定於 `UI_SOURCE.json` 記錄的 `ea20229…`；本次行為核對使用 `d23d271…`，不等同已升級或複製全部宿主程式。

## 同一 Agent 項目的兩種卡片狀態

| 卡片 | 內容與操作 |
| --- | --- |
| 入口狀態 | 客服名稱、Agent 編號、真實渠道狀態、待本人處理數量與「開啟收件匣」主要按鈕；管理及 WhatsApp 接駁為次要操作。 |
| 展開工作區 | 返回客服卡片、實際運行狀態、「收件匣／知識庫／管理」主要檢視，預設進入收件匣。 |

入口與展開工作區共用同一已登記 Agent／instance，不建立兩個工作台項目。工作區只有一個外框，對話不再藏在基本設定。收件匣顯示對話列表、訊息／回覆及上下文；知識庫管理 FAQ 與待核對記憶；管理集中商戶設定、全域回覆政策、渠道狀態及接駁教學。舊 basic／training／connect 內部 ID 可保留作相容，不規定使用者仍須沿用舊分頁名稱。

知識庫中的「教客服」表示用聊天及對答示範建立可檢查的商戶記憶，不是修改模型權重；原文待確認，不自動當作 FAQ。管理保留行業、自訂指令及六種建議回覆模式。WhatsApp 手機與 AI 模型狀態分開呈現；手機燈號按實際連線檢查，沒有模型金鑰不否定手機連線。裝置已連接仍不代表收件、發送開關或送達已驗證。

回覆路線包括 FAQ-only、明確接駁的本機原生 Codex CLI 與選用模型 API。原生 CLI 沿用 ChatGPT 登入及帳戶額度，建立獨立受限工作，不喚醒目前左側聊天；這個「原生」也不表示宿主 renderer／卡片安裝已完成。AI 後備及自動發送需分別確認，不能因測試成功就更改全域政策。詳見 [安裝](INSTALL.md#原生-codex-與選用-api) 與 [收件匣](LIVE_INBOX.md)。

此交互參考 [Zendesk Agent Workspace 官方說明](https://support.zendesk.com/hc/en-us/articles/4408821259930-About-the-Zendesk-Agent-Workspace/) 及[使用者提供的官方示範](https://www.zendesk.hk/demo/) 的同頁對話與上下文方式，不接入 Zendesk 或複製其素材。只呈現本版已有的對話及權限；不加入無後台支援的 CRM、分派、SLA 或結案操作。

## 固定最小與最大尺寸

「固定尺寸」在本設計中指**每種卡片都有固定、版本化的尺寸範圍**。使用者可在範圍內放大或縮小，不能任意突破下限與上限。每次新建使用預設尺寸；重新開啟使用上次有效尺寸。這些值由開發者維護，日常設定不要求商戶填寫數字。

以下是客服插件第一版整合規格，**不是目前原生卡片已有的數值，也尚未由本機版強制執行**。數值指整張卡片的外框，包含邊框與內距，單位為 CSS px；括號為 24px 格數，順序均為寬 × 高。

| 卡片 | 固定最小尺寸 | 預設尺寸 | 固定最大尺寸 |
| --- | --- | --- | --- |
| 入口狀態 | 288 × 240（12 × 10 格） | 360 × 264（15 × 11 格） | 576 × 384（24 × 16 格） |
| 展開工作區 | 576 × 480（24 × 20 格） | 864 × 768（36 × 32 格） | 1152 × 960（48 × 40 格） |

入口卡片需要容納名稱、狀態與操作；工作區需要容納主要檢視及可閱讀的對話與欄位。同一卡片在入口與展開狀態使用不同尺寸下限；身份及資料仍是同一實例。所有上限均低於宿主每頁 48 行的高度限制；未來改值需更新此表與驗收，不能只改 CSS。

### 計算規則

1. 使用宿主提供的**可用畫布範圍**，扣除側欄、頂列及既有留白；不要用整個螢幕寬度計算。
2. 拖動把手改變的是卡片外框尺寸，不是文字或整個網頁的比例；每次增減對齊 24px 方格。
3. 有效最大寬度是「卡片最大寬度」與「畫布可用寬度向下取整至 24px」的較小值。有效最大高度是卡片最大高度與宿主單頁可用高度的較小值。
4. 空間足夠時，先對齊方格，再把要求尺寸限制在最小與有效最大之間：`size = clamp(snap(requested), minimum, effectiveMaximum)`。直接輸入尺寸時同樣檢查。
5. 可用空間小於最小尺寸時，先切換窄螢幕閱讀模式，不執行上下限相反的 `clamp`。畫布已有其他卡片則交由宿主檢查碰撞，不能強行覆蓋。
6. 瀏覽器縮放及系統文字放大照常可用；不得用 `transform: scale()` 把文字縮細來滿足卡片尺寸。

### 內容放不下時

- 桌面工作區維持使用者選擇的有效尺寸。頂部返回／主要檢視及操作結果仍可到達，不因長內容突破卡片最大高度。864px 預設卡片使用對話列表＋訊息雙欄，上下文以抽屜開啟；可用內容寬達 1080px 才同時顯示三欄。
- 收件匣列表及時間線可各自捲動，回覆操作可透過鍵盤到達；避免在時間線再嵌套多層捲動。知識庫與管理長表單使用主要內容區捲動。自動更新保留閱讀位置及各客戶未送出文字，不搶走編輯焦點。
- 縮小入口卡片時可減少說明文字，但名稱、真實渠道狀態及「開啟收件匣」按鈕必須保留。
- 宿主如支援收合，將收合狀態分開保存；展開恢復原尺寸。收合不是把正常最小高度改成任意值。卡片內的入口／工作區切換不代表宿主收合功能已實作。

### 手機及窄畫布

當卡片不足以維持可閱讀雙欄時，收件匣一次顯示列表或所選詳情，透過返回列表切換；上下文按需開啟抽屜，關閉後焦點返回原操作。主要檢視及各客戶輸入保留，不把三欄壓縮到手機寬度。

當可用畫布不足該卡片最小寬度時，卡片改為單欄、使用畫布全寬，高度隨內容延伸，由頁面垂直捲動。這是明確的閱讀模式例外，暫停自由拖移／縮放，保留欄位及主要操作，不產生水平捲動。

閱讀模式不得把臨時尺寸寫回桌面偏好。畫布恢復足夠寬度後，恢復桌面尺寸與位置並重新檢查邊界。最窄驗收視窗為 320 CSS px；可編輯欄位文字至少 16px，觸控目標至少約 44px。

## 移動及保存排版

- 沿用宿主的「調整排版」模式與指定把手。拖動輸入框、選取文字、操作下拉選單或訓練對話時不得移動整張卡片。
- 拖移只改變位置，縮放只改變尺寸；均吸附原生方格，不移出畫布、不跨越不允許的頁界、不蓋住其他卡片。
- 空間不足時保留上一個有效排列並提示使用者；不自動新增頁、不刪除卡片。增加頁面遵循宿主的明確操作及頁數上限。
- 支援滑鼠／觸控把手、方向鍵、取消操作及還原排版。取消恢復操作前位置；失去指標控制時不得保存中途無效位置。
- 排版偏好至少記錄版本、工作空間、使用者、Agent ID、卡片種類、頁碼、位置及尺寸。只在成功完成調整後保存；不得儲存 API 金鑰、商戶指令或聊天內容。
- 重新載入時核對版本與數值、限制越界尺寸；新版本尺寸規格較嚴格時保留可用排列或回到預設，商戶資料及訓練記憶不受影響。

## 宿主與插件分工

| 藍圖工作室負責 | 客服插件負責 |
| --- | --- |
| 工作空間身份、權限、外層導覽及主題 | 基本設定、行業與自訂回覆指令 |
| 卡片註冊、移動、縮放、碰撞及排版偏好 | 訓練對話、待確認記憶及批准流程 |
| 原生元件、焦點及可及性規則 | AI／WhatsApp 接駁流程及真實狀態 |
| 插件載入／卸載與能力授權 | 保留未儲存輸入，顯示操作成功或失敗 |

工作室內置的是卡片及操作入口；客服後台與執行器獨立運行、開發、發行及部署。正式接入須另外定義宿主與客服服務的認證、資料範圍及生命週期，不能直接把本機管理員登入搬成多使用者插件。本機版仍是單商戶單程序，沒有宣稱完成多租戶隔離或真實訊息收發。後台開發次序見 [開發計劃](DEVELOPMENT_PLAN.md)。

## 實作與驗收狀態

| 項目 | 本次狀態 |
| --- | --- |
| 精簡入口與同一卡片的收件匣／知識庫／管理工作區 | 本次交互規格；本機實作及瀏覽器驗收按當次結果另記，不能由文件視為已通過 |
| 行業、指令、訓練記憶、接駁介面 | 已實作；真實帳戶連接仍需使用者設定及驗收 |
| 桌面及 320px 手機排版、切換保留輸入 | 舊版已有核對；本次列表／詳情、上下文及輸入保留按新版本重新驗收 |
| 單一卡片項目、不替換宿主內容及固定尺寸範圍 | 已記錄於本規格及 AGENT_UI_CONTRACT；宿主尺寸引擎仍待整合 |
| 原生卡片註冊、拖移、縮放、尺寸限制與偏好保存 | 待宿主整合；本機版目前是隨頁面排列的卡片 |
| 寫入測試工作室／正式上線 | 未執行 |

完成原生整合的驗收須涵蓋：同一卡片兩種狀態的最小／預設／最大尺寸、越界輸入、碰撞拒絕、取消拖動、鍵盤調整、跨重啟恢復、手機列表／詳情往返、上下文抽屜、瀏覽器 200% 縮放，以及切換客戶／知識庫／管理時不丟失輸入。尚未完成這些驗收時，不把相應能力標為已完成。

## 宿主內容保護及真實驗收

客服不能讀取後取得全域寫入能力，不能重設或覆蓋宿主總覽、工作、資料、導覽、全域路由、CSS 或資料表。對話及核對操作留在自身卡片；舊整頁診斷工具不列入宿主安裝產物。缺少 renderer／受限 API 時，列出缺項並先完成相容層。

真實 WhatsApp 驗收包含本人掃碼、指定測試號碼、同筆來訊、人工核對回覆及手機收件。卡片展示、離線規則或網頁扮演客人的成功，不能代替該渠道證據。

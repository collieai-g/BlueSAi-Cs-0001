# 知識理解與人工對話學習驗證

日期：2026-10-26。本文記錄本功能開發時的範圍；來源與完整 CI 以該 PR 的固定 commit 為準。私人商戶／電話／auth／SQLite／截圖及原始模型輸出不加入本倉庫。

## 真正原生模型與合成資料

使用本機已登入 ChatGPT 的受限 Codex CLI，在記憶體資料庫及假渠道驗證以下四條路線，全部通過：

1. FAQ 問題為「合成工作室怎樣管理 AI」，客人改問「合成工作室可以新增 AI 卡片嗎」；模型返回有批准事實來源的 answer，Engine 交假 provider 接受。這不是字面相同的 FAQ 比對。
2. 原生 `learn` 整理「查到貨時間前先確認貨品，未有物流資料不承諾日期」，分類為 procedure 並保留待確認；沒有退回離線原文複製路線。
3. 合成人工回覆由假渠道接受後，獨立學習服務保留 staff 來源，模型提出 procedure；正式知識 revision 在候選時不變，只有合成商戶明確批准才加入知識。
4. 下一位合成客戶詢問到貨，模型引用已批准流程產生 clarify，保存草稿；流程沒有被用來證明到貨日期或自動發送。

本輪四階段合成驗證約 36 秒；假 provider 接受兩次，真正 WhatsApp 發送零次。這證明模型、應用來源檢查與資料回存路線，不等於已在 02 工作室安裝或向真實客戶發送本功能。

## 原生完成事件與停止

Windows 實測曾觀察 CLI 在約 5.5 秒已發出 agent_message 及 turn.completed，但未關閉 stdio，舊邏輯一直等程序 close 後誤報 25 秒超時。

新邏輯只接受已收到答案的單次完整回合；保留 150ms 寬限讓自然 close 優先，未退出時只終止該次 owned exec 並清理。期間非法工具、錯誤、新回合或額外輸出仍拒絕；schema、來源及 25 秒推理上限保留。逾時／取消的主錯碼不再被清理錯誤掩蓋。

隔離測試包含真正合成 Node 父子程序取消及「完成後不退出」的程序終止；沒有停止使用者的其他 Codex 程序。

正常新來訊、人工接手或應用期限造成的 caller 取消，不改寫模型的已驗證狀態或驗證時間；尚未驗證也不會因取消變成已連線。真正推理逾時、遠端失敗與清理故障仍會報錯，並發取消不能蓋過另一項較新的真故障。Windows 終止會有界等待該次 owned taskkill 及 child close，再嘗試釋放暫存目錄。

## 介面與後台

隔離瀏覽器驗證模型可用／待檢查、三類建議、來源依據、待補問題／衝突確認、來源失效禁採用、採用讀回、未儲存修改保留、自動整理保存讀回，以及 320px 無橫向溢出。未以隔離畫面作真實渠道送達證明。

實際分析狀態 `analyzed` 顯示為「已分析」並停用重複提交；模型沒有提出新建議時，畫面如實顯示，不聲稱已建立正式記憶。

測試涵蓋只收錄已送 staff、保留角色、常見個人識別資料遮罩、來源變更、模型切換、超時／停止、停用與 Promise 回存競態、重啟不重跑不明工作、跨個案去重、拒絕後不反覆重提、容量界線、候選不取消人工發送，以及正式批准才改知識版本。

機器辨識不能保證識別所有自由文字姓名、地址或一次例外。建議保留待本人核對，沒有自動批准政策。

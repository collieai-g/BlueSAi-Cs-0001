# 由工作台呼叫 Codex 與 DOT

這是 [客服專用 Harness](HARNESS_ENGINEERING.md) 的左右交接構件：同一工作的要求與來源交出去，結果回到右側供本人核對。交接、保存、驗收及對客動作分開；工具不能因左側較有能力而擴大權限。

這個階段讓商戶在客服工作台準備任務，再交給目前使用的 Codex／DOT 智能 Agent。沿用已有的登入對話與權限，不要求另一個 DOT 帳戶、模型 API 金鑰或新訂閱。OpenAI API 設定保留為明確選用的其他路線。

此文件描述「管理」內的一般任務與商戶知識快照。收件匣另有綁定所選客戶最新版本的 DOT 草稿流程，見 [LIVE_INBOX.md](LIVE_INBOX.md)；兩者都不直接向客戶發送。自傳連線測試不提供 DOT 草稿操作。

## 操作流程

1. 在「管理」的一般 Codex／DOT 任務填寫想處理的要求，按「準備任務」。客服服務保存當時商戶設定及已確認、未過期記憶的快照；畫面展示將交出的內容。
2. 按「呼叫 Codex／DOT」先向後台核對最新任務，再按一次提出原生交接。使用者檢查後，才送到目前對話；若等待太久或切換畫面，須重新核對。若在支援的內嵌 Agent 介面內，則使用宿主提供的訊息能力。
3. Agent 根據選定任務及資料提出分析、建議或客服草稿。可用網站工具時，讀取該任務並保存結果；其他情況可把回傳 JSON 貼回工作台。
4. 工作台保存回傳結果供人手核對，不直接向客戶發送，也不把內容自動加入已批准記憶。

不支援原生交接的瀏覽器仍可複製任務，貼到已有的 Codex／DOT 對話。按鍵不會偷偷打開另一個未知對話，亦不儲存 ChatGPT 登入密碼。此階段由使用者主動交出任務；沒有按鍵操作時，不會自動喚起 Agent。

## 官方宿主能力

內置瀏覽器使用 Browser Annotation API：在使用者按鍵事件內，同步呼叫 `document.oai.annotation.request(visibleElement, options)`。目標是可見的任務內容；簡短的 initialComment 只提示目前 Agent 使用該內容。API 回傳 accepted 只代表瀏覽器接受請求，不能證明已送出或開始工作；最後送出仍由使用者完成。[官方說明](https://learn.chatgpt.com/docs/annotations-extensibility)

網站以 `document.modelContext.registerTool` 提供選定任務的讀取與結果保存工具，重用目前頁面登入及後端權限，不要求另裝 MCP 服務。功能按宿主、模型及帳戶設定而定，使用前偵測支援；普通瀏覽器保留人工操作。[官方網站工具說明](https://learn.chatgpt.com/docs/webmcp)

支援內嵌 UI 的宿主可使用 `window.openai.sendFollowUpMessage` 交到目前 AI 對話，並清楚標示為宿主提交；這不是指定私人 DOT 對話的 API，也不表示任務已完成。[官方元件介面](https://developers.openai.com/plugins/reference)

## 任務與結果

`dot_tasks` 保存任務 ID、要求、資料版本、不可改寫的快照、對應代碼、任務文字、狀態及回傳結果。對應代碼只用來避免把結果放錯任務，不證明回覆者的身份。

| 狀態 | 可確認的事 |
| --- | --- |
| prepared | 任務已保存在本機，尚未交到 Agent。 |
| copied | 任務已複製；未證明貼上或送出。 |
| opened | 宿主接受原生交接請求；仍需使用者送出。 |
| host_submitted | 內嵌宿主的訊息提交已返回；未證明 Agent 已執行。 |
| result_saved | 與任務編號、代碼相符的結果已保存，待核對。 |
| cancelled | 任務已取消，不能再保存新結果。 |

重複準備相同任務使用唯一操作鍵取回原任務，不重建快照。同一鍵用於不同要求會被拒絕。每次更新要帶目前版本，避免兩個畫面覆寫；取消或保存結果後不能再更改。

任務只包含指定商戶設定和已批准、未過期的記憶；不含接駁金鑰、管理員密碼或客戶對話。Agent 網站工具只處理使用者當前選定的任務。設定、知識版本、批准或有效期改變時，舊任務不能當作目前資料使用，也不能保存新結果，需準備新任務。

任務資料只經由目前工作台 session 的同源 API 讀寫；網站工具的保存能力只保留草稿，沒有對客發送、批准知識、退款或改單權限。最多保存 100 項任務，清單展示最近 20 項。

原生按鍵必須同步執行，不能先等待網絡。介面先讀取最新任務，再給予五秒、一次性的確認機會；本頁修改、其他分頁的更新訊號、失去焦點或切換畫面會撤回確認。呼叫及複製時也同步檢查快照內資料的有效期；複製另先讀回後台。讀回與原生呼叫之間仍可能有另一個程序更改資料，故交出內容只代表保存時的快照，不能宣稱完全排除競態。網站工具讀取及結果保存會再次由後台核對最新版本。

清單只顯示最近 20 項，但已選任務獨立按 ID 讀取；即使跌出清單，也不會失去目前的任務。任務歷史不會自動交給 Agent。

## 與後台自動服務的分工

工作台呼叫 Agent 是使用者發起的協作流程。WhatsApp 收件、30 秒交接期限、人工控制及發送仍由獨立客服後台執行。準備任務不會停掉或延長期限，也不會把「已交出」當作客戶已收到答案。

未來如需關閉畫面後仍由來訊自動啟動 Agent，另按支援的事件／背景執行路線開發及驗收。MCP Events 不是本階段按鍵呼叫的必要條件；它也不能取代本地期限或真實發送檢查。

## 資料相容性

增量遷移 v2 只新增 dot_tasks 及索引，保留 v1 的 response_windows、handoff_tasks 及商戶資料。實際服務升級前須停止並備份；開發驗證使用記憶體或暫存資料庫。新增任務不會更改模型設定或清除既有接駁。

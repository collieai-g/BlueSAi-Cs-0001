# 收件匣、FAQ 優先與三種回覆路線

版本：0.4.0-preview.2。客服仍只有一張卡片，不更改宿主總覽、工作、資料或導覽。

## FAQ 優先，再選是否需要 AI

WhatsApp 新私人文字來訊經已驗證的本機接駁進入客服。卡片展開預設進入「收件匣」，列表及所選對話按客戶分開；透過同一登入會話的 SSE 收到變更提示後讀回實際內容，輪詢作後備。人工可以接手、編寫及發送，更新不清空正在輸入的內容。FAQ 與記憶在知識庫維護，全域處理政策與渠道教學移到管理；詳見 [介面設計](UI_DESIGN.md)。

啟用「知識庫優先」（`enabled=true`）後，第一層使用本人建立的「客戶問題 → 已確認答案」。完整問題經 Unicode、空白、大小寫及句尾問號正規化後，只有唯一、已批准、未過期的答案才原文採用。這一層不呼叫模型，也不把普通筆記或相似字眼猜成命中。`automaticKnowledge` 保留原有獨立授權：開啟且通過渠道條件才自動發送，否則存草稿。

沒有 FAQ 命中時，預設保存來訊並轉本人；只有明確開啟 `aiFallback` 才使用已接駁的 AI。退款／投訴、答案衝突、缺乏可靠依據及其他須本人判斷的安排，仍轉人工，不能以 AI 猜測繞過。回覆路線如下：

| 模式 | 未命中 FAQ 後 | 執行與額度 |
| --- | --- | --- |
| FAQ-only／人工 | 提示本人，可手動交目前 Codex／DOT 草擬 | 不需背景模型；人工交接仍由本人送出 |
| 原生 Codex CLI | 獨立本機 CLI 工作處理單一客戶有限上下文 | 沿用可用的 ChatGPT CLI 登入，使用帳戶額度；不另要 API key |
| 模型 API | 使用本人另行接駁的 API adapter | 自己的模型及 API 額度 |

`aiFallback` 預設 false，開啟需 `enabled=true` 且 adapter 已配置可用。`automaticAi` 亦預設 false，需先開啟 fallback；它不取代 `automaticKnowledge`，更不取代渠道發送授權。AI 回傳 `answer` 必須有本次已批准且仍有效的來源，經後台核對後才有資格按授權自動發送。`clarify` 先保存待本人確認草稿；無依據、退款／衝突、生成失敗、輸出無效或逾時轉人工。模型寫出「可以發送」不構成授權。

轉人工時保留原來對話並建立持久待處理提示。本人可開啟瀏覽器通知，允許後由仍在運行的頁面提示；不等於手機推播、電郵或喚醒目前左側聊天。獨立 CLI 工作可在頁面關閉時由仍運行的核心處理，但不能控制當前 Codex／DOT 對話；關頁後的外部通知及通用背景 DOT 尚未提供。

## 原生工作與目前左側聊天分開

在管理按原生 Codex 接駁並明確同意後，後台先核對 CLI 版本、ChatGPT 登入及一次真正合成回覆；全部成功才切換 adapter。連接不修改上述政策，也不開啟自動發送。登入成功、合成推理成功及真實客戶收件是三種獨立證據。

每次原生生成是獨立 ephemeral 工作，固定最多 25 秒；只傳入單一客戶有限對話及批准來源。shell、apps、MCP、plugins、hooks、多 agent、電腦、瀏覽器、圖片、網頁搜尋及 Skill discovery 等工具關閉。使用固定 JSON schema，後台再驗證結構、來源、版本及決策。read-only 字樣及 schema 合法均不能單獨保證資料隔離或答案正確。

CLI 沿用原來登入位置，不搬移 auth。`BLUEPRINT_DATA_DIR/codex-jobs` 是倉庫外的臨時 schema 工作位置，完成後清理；prompt 經 stdin 傳入，不寫到該目錄。詳細安裝及故障處理見 [INSTALL.md](INSTALL.md#原生-codex-與選用-api)。

## 本人主動交給目前 Codex／DOT

按「交給 DOT 閱讀」會把所選對話的任務交到目前 Codex／DOT 編輯器，由本人送出。頁面工具讀取實際待處理清單及所選對話，只保存未驗證草稿。當前客戶、新來訊、人工控制、知識 revision 或有效來源改變時，舊草稿憑證失效，須重新閱讀。工具沒有發送及修改知識的權限。

DOT 草稿可採用到人工回覆，再由本人核對及發送。這條路使用目前 Codex／DOT 的模型，與獨立 CLI／API fallback 不同；客服不需要另外提供模型 API key。知識庫模式下的訓練原文仍在本機保存為待確認記憶，不因啟用 fallback 就自動改寫或批准知識。

## 接收與回覆分開確認

本機工作台在 WhatsApp 手機連線後，自動準備接收所有新的一對一私人文字，不需要另行填寫收件表單或登記號碼。手機連線及實際收件仍是不同狀態：只有收件入口、帳戶及範圍核對成功才顯示可接收；準備失敗可重試。本人在對話中逐筆按發送才會人工回覆最近來訊的客戶，不開放陌生號碼或群發。啟動前未曾交付的訊息不保證補回；已接收但尚未轉送的待辦須保留並核對原帳戶。新來訊依已保存的知識庫／AI 政策處理；已啟用自動回覆時，符合有效來源及渠道條件的答案可自動發送，人工接手仍優先。移除本機額外的逐筆批准限制，不重跑舊來訊或補發舊草稿。

卡片不再提供指定號碼測試表單或切回測試名單的操作。其他採獨立授權的 runtime 需要本人確認接收範圍；本機工作台在連結後自動準備。只處理可可靠識別的新私人文字。群組、廣播、歷史同步、圖片、語音及附件不在本版支援範圍；自身訊息須另外選擇預設只讀測試；本人對話回覆另行明確授權。斷線期間未獲 provider 交付的訊息不能保證補回。

在提供本人測試能力的其他 runtime，如暫時沒有另一個帳戶，可另外勾選「自己傳給自己」連線測試。只有本人明確開啟後、由同一已連結帳戶傳給自己的新文字才會進入卡片，預設只讀，且不建立客戶待處理任務或通知。

要試 Hello 的真正回覆，再明確開啟獨立「本人對話回覆測試」。核心與橋接核對同一帳戶及當次隨機 grant，只對授權之後的新自身文字開放唯一、已批准且有效的完整 FAQ 自動回覆，以及專用人工提交。自動 FAQ 同時要求本人測試 enabled／automaticFaq 及全域 enabled／automaticKnowledge，不改全域政策。它不呼叫 CLI、API 或 DOT；未命中 FAQ 不猜答。人工提交會原子切至 self_human 並排隊；明確交回 self_auto 只影響下一筆新來訊。舊 Hello 不重跑，須在手機再傳一則新 Hello。

已由客服發出的訊息，按 ID 與 address 攔截回聲，不能只靠 fromMe 判斷；不確定發送結果即停止該測試，不自動重送。重啟、斷線、換帳戶或撤銷均關閉 grant。本人測試仍不算外部顧客來訊或雙向服務驗收，亦不擴大任何對外發送範圍。[操作、接口與驗收界線](SELF_REPLY_TEST.md)

在其他採獨立授權的 runtime，單獨開啟收件不啟用發送。「允許回覆最近來訊客戶」只允許回覆已實際傳訊過來、可可靠識別、最近 24 小時內的客戶，不允許任意號碼或廣播。核心及橋接分別核對範圍；回覆授權在重啟／斷線後關閉。收件模式切換時先關閉發送及清理已不在範圍的排隊內文。

短暫離線後，WhatsApp 可能把新來訊標為補送，或稍後才提供可解密的內容。橋接仍須核對來訊時間、原有帳戶及接收授權，只接收五分鐘內且不早於收件授權的新私人文字；同一筆已轉送訊息不會因補送而重複處理。支援限時訊息包裝中的純文字，圖片、語音及閱後即焚媒體仍不轉送。這不會開啟聊天歷史同步，長時間停機的舊訊息不保證補回。

本機與其他 runtime 均依「已確認答案自動回覆」及「AI 答案自動發送」的已保存設定處理；本機不再額外強制只產生草稿。收件範圍、回覆授權、相應政策、人工狀態、最新版本、有效來源及最近 24 小時來訊條件均符合時才實際發送；否則保留草稿或轉人工。人工接手優先，交回助手才可恢復相應自動處理。不確定的發送結果不自動重送；accepted、delivered、read 分開顯示。

## 失敗、關閉與重新啟動

AI 失敗或達到 25 秒原生期限時，後台保留來訊及待處理狀態，轉人工；不無限重試、不擅自切換另一個付費模式。可關閉 `automaticAi` 保留草稿核對，或關閉 `aiFallback` 回到 FAQ-only／人工，已確認 FAQ 的原授權不被這兩個新開關取代。

本機電腦、客服核心與渠道橋接必須運行，原生模式另需可用 CLI 登入及對外模型連線。重啟後重讀同一對話／工作與回執，再檢查接駁及發送授權；不能把舊 `sending`／未知結果當成未發送再重做。CLI 合成測試失敗顯示固定失敗類別，不展示原始客戶內容、憑證或私密程序日誌。

## 資料與驗收

Schema 5 新增 FAQ 對照及本機收件箱政策；schema 6 另以 self_test_reply_links 保存本人測試 grant、來訊與 operation ID 的對應。增量遷移保留原有商戶、已批准知識、人工狀態、對話及期限記錄，不因保存關聯就沿用上次 grant。空白商戶欄位保持空白；純知識庫／人工模式的發送不要求代填這些欄位。私人手機授權、資料庫、備份及金鑰留在 Git 之外。

程式測試使用隔離暫存資料。本人對話的真收件、FAQ 回覆及人工回覆按 SELF_REPLY_TEST 另外驗收；真正外部顧客服務仍需要另一個 WhatsApp 帳戶傳入，卡片讀回同一筆訊息，並在收件手機核對人工／已確認答案回覆。先前本人掃碼及 `open` 證據不等於這些雙向訊息測試已通過。

## 卡片看不到來訊時

本機電腦重新啟動後，先啟動客服及 WhatsApp 接駁程序，再恢復裝置連線；開著瀏覽器頁面不會令已停止的後台自動運行。保留的手機登入狀態通常可直接重連，只有登入失效時才需要本人重新掃碼。發送權限仍須依已確認的範圍重新啟用。

卡片可檢查 WhatsApp 連線、收件設定及收件計數。計數只包含此接駁程序啟動後的事件數、轉送數、時間及固定拒絕原因，不包含客戶文字、姓名、號碼、訊息 ID、QR 或金鑰。收到 provider 事件並不代表訊息已保存到客服；應另核對實際來訊，不能把連線正常或空白計數當成真實收件驗收。

# 即時對話、知識庫直接回覆與 DOT 草稿

版本：0.4.0-preview.1。客服仍只有一張卡片，不更改宿主總覽、工作、資料或導覽。

## 兩層處理

WhatsApp 新私人文字來訊經已驗證的本機接駁進入客服。卡片「即時對話」保持可見，按客戶分開，透過同一登入會話的 SSE 收到變更提示後讀回實際內容；輪詢作後備。人工可以接手、編寫及發送，更新不清空正在輸入的內容。

啟用「知識庫優先」後，第一層使用本人建立的「客戶問題 → 已確認答案」。完整問題經 Unicode、空白、大小寫及句尾問號正規化後，只有唯一、已批准、未過期的答案才原文回覆。沒有語意模型，也不把普通筆記或相似字眼猜成答案。退款、投訴、衝突、過期或沒有答案，立即轉第二層。

第二層保存原來對話並建立持久待處理提示。卡片顯示待本人／DOT 處理；本人可開啟瀏覽器通知，允許後由仍在運行的頁面提示。這不等於已發送手機推播、電郵或已喚醒背景 DOT。關閉頁面後的外部通知及持續 DOT 執行器尚未提供。

按「交給 DOT 閱讀」會把所選對話的任務交到目前 Codex／DOT 編輯器，由本人送出。頁面工具讀取實際待處理清單及所選對話，只保存未驗證草稿。當前客戶、新來訊、人工控制、知識 revision 或有效來源改變時，舊草稿憑證失效，須重新閱讀。工具沒有發送及修改知識的權限。

DOT 草稿可採用到人工回覆，再由本人核對及發送。它仍使用目前 Codex／DOT 的模型；客服不需要另外提供模型 API key。知識庫模式下的訓練原文在本機保存為待確認記憶，不呼叫已設定的背景模型。

## 接收與回覆分開確認

本機橋接保留原有最多三個指定號碼測試模式。新增「接收所有新私人文字訊息」需要本人在卡片明確確認，只收連結帳戶之後收到的可可靠識別的新私人文字。群組、廣播、自己傳給自己、歷史同步、圖片、語音及附件不在本版支援範圍；斷線期間未獲 provider 交付的訊息不能保證補回。

單獨開啟收件不啟用發送。「允許回覆最近來訊客戶」只允許回覆已實際傳訊過來、可可靠識別、最近 24 小時內的客戶，不允許任意號碼或廣播。核心及橋接分別核對範圍；回覆授權在重啟／斷線後關閉。收件模式切換時先關閉發送及清理已不在範圍的排隊內文。

「已確認答案自動回覆」亦要另外開啟。收件範圍、回覆授權及自動答案三項均符合時才實際發送；否則保存草稿。人工接手優先，交回知識庫才恢復自動處理。不確定的發送結果不自動重送；accepted、delivered、read 分開顯示。

## 資料與驗收

Schema 5 只新增 FAQ 對照及本機收件箱政策，保留原有商戶、已批准知識、人工狀態、對話及期限記錄。空白商戶欄位保持空白；純知識庫／人工模式的發送不要求代填這些欄位。私人手機授權、資料庫、備份及金鑰留在 Git 之外。

程式測試使用隔離暫存資料。真實驗收仍需要另一個 WhatsApp 帳戶傳入，卡片讀回同一筆訊息，並在收件手機核對人工／已確認答案回覆。先前本人掃碼及 `open` 證據不等於這些雙向訊息測試已通過。

## 架構與既有功能

工作室內提供原生客服卡片入口；客服後台獨立運行及部署。工作室負責外層導覽、公司資料、權限與操作入口；客服後台負責 WhatsApp、AI 執行、計時、發送與人工接管。

基線已完成本機 3101 工作台、入口卡片、同一卡片內的基本設定／訓練／接駁、行業、自訂指令、六種建議回覆模式、待確認記憶，以及模型／WhatsApp 接駁介面。卡片的原生移動、縮放與固定尺寸限制按 [插件設計規格](BLUEPRINT_PLUGIN_DESIGN.md) 另行整合。3101 工作台不啟動收件 webhook 或發送 worker；本階段擴充 3100 服務的共用 Engine。

## 第一里程碑 可靠交接流程

以虛構資料和模擬模型／渠道完成：收到問題 → 草稿 → 超時轉人工 → 人工接管 → 保存人工回覆結果。

1. 新的 AI 待答問題在收件交易內保存 30 秒期限；連續來訊沿用最早未處理問題的期限，重複事件不重建期限。
2. 獨立期限監察不等待模型、供應商或網頁。到期原子轉為等待人工、取消未提交的 AI 回覆並建立一項本地交接工作。
3. 草稿和發送佇列不算已提交回覆；生成完成、批准及提交發送前均重新核對期限。人工接管後，遲到的模型結果不得重新建立或發送 AI 回覆。
4. 發送已提交供應商後保留在途證據；結果不明仍是 uncertain，不自動重試。本地交接工作不代表私人 WhatsApp 已收到通知。
5. 增量、版本化、交易式資料遷移保留商戶設定、批准狀態、對話及歷史。舊對話不倒填期限；重啟立即補處理已保存的過期期限。

驗收涵蓋模型持續等待、30 秒邊界、連續與重複來訊、草稿及排隊逾時、重啟、人工接管／交回、遲到結果、在途結果不明及人工回覆保存。測試使用可控制時鐘及測試替身，不等待真實 30 秒，也不呼叫真實外部服務。

此里程碑已審查並合併 PR #1：2026-10-24 全套 49 項測試及語法檢查通過，其中 19 項是新增交接測試。3101 工作台已在備份後升級共用資料庫；3100 原有程序未重啟，不能寫成正式收發服務已升級。

## 第二里程碑 按鍵呼叫 Codex 與 DOT

整體以 Codex 與 DOT 智能 Agent 配合。商戶在工作台按鍵準備任務，使用原生交接把內容送到目前對話；不要求另外建立 DOT 帳戶或提供 API 金鑰。Agent 使用已確認資料處理任務，再把結果保存為待核對草稿。

優先完成：持久任務與資料快照 → 原生按鍵交接 → 選定任務網站工具 → 結果保存與版本核對。原生交接要求使用者檢查及送出，開啟交接、宿主提交、Agent 處理與結果保存分別記錄。詳細方式見 [Codex 與 DOT 任務交接](CODEX_DOT_HANDOFF.md)。

本機程式已實作，全套 74 項測試及語法檢查通過。內置瀏覽器已完成選定任務讀取、Agent 草稿回存、複製備援及手機版面測試。Agent 控制瀏覽器期間，原生 API 拒絕開啟要求，介面正確顯示未接受；使用者親自按鍵並送出的原生交接仍待實測，不宣稱完整宿主交接已通過。詳見 [驗證記錄](CODEX_DOT_VERIFICATION.md)。

## 後續開發次序

| 階段 | 工作 | 接入門檻 |
| --- | --- | --- |
| 按鍵協作驗證 | 原生交接、網站工具、持久任務與結果核對 | 使用目前 Codex／DOT 對話，不要求新模型金鑰；送出由使用者確認 |
| 渠道能力驗證 | WhatsApp 公司手機回聲、同號共存與狀態能力 | 實際帳戶及渠道逐項核對，真實驗證另經授權 |
| 藍圖資料與 DOT 整合 | 固定 Integration Contract、公司核准知識、同步 outbox、指令 inbox、DOT adapter | 共同模擬樣本驗證去重、斷線、撤銷與遲到答案 |
| 私人手機閉環 | 擁有人身份、個案引用、明確「回覆客戶」指令、通知傳送及查證 | 內部備註不外發；同一指令只建立一次發送 |
| 原生介面與上線驗收 | 宿主卡片註冊、移動／縮放、尺寸限制及運行狀態 | 同一卡片內收件匣／知識庫／管理；列表／詳情、上下文、桌面、手機及真實渠道驗收 |

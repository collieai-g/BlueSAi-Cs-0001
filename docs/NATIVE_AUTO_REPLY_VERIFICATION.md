## 已核對

- 本機 Codex CLI `0.164.0-alpha.11.1` 支援所需非互動旗標；透過 `login status` 只核對登入類型為 ChatGPT，沒有讀取或複製登入憑證。
- `createCodexAgent.check()` 使用公開合成問題及來源完成一次真正模型推理，回傳有效 `answer` 與指定來源。未提供另外的模型 API key。
- 另以記憶體資料庫、合成商戶知識及假渠道執行完整 `Engine.receive → Codex CLI → 版本／來源檢查 → 自動排隊 → dispatch`。結果為 `codex-cli / answer / accepted`，假發送器呼叫一次；真正 WhatsApp 發送零次。
- Node 24.22 全套測試 **224/224** 通過，包括 FAQ 優先、政策依賴、人工接手／新來訊／政策／來源／provider 變更、晚回覆、重啟選路、來源退款類別及失敗轉人工。
- 原生 adapter 測試涵蓋環境秘密不繼承、stdin 輸入、禁工具設定、輸出結構／來源、畸形 JSONL、已完成動作聲稱、未完成 turn、非零退出、超大輸出、逾時及取消。
- Windows 使用真正的合成 Node 父子程序核對取消後兩個 PID 都終止、工作目錄清空；該測試不使用模型、登入或 WhatsApp。Linux 程序群組路線由跨平台 CI 另外核對，不能以 Windows 結果代替。
- 隔離瀏覽器夾具核對未同意不能接駁、未接模型不能啟用 AI、接駁不儲存政策、草稿／自動發送分開、失敗保留原政策、不支援時禁用、重啟須重新檢查。停用會清除 AI 勾選並保留其他未儲存 FAQ 選擇。
- JavaScript 語法及差異格式檢查通過。卡片根節點、受限 API 及宿主內容邊界保留。

## 版本差異及失敗方式

本機 CLI 的嚴格設定檢查拒絕舊 `tools.view_image` 設定，實作使用已核實的 `features.view_image=false`。工具、插件、hooks、瀏覽器與電腦操作保持停用，沒有回退至廣泛權限。

這個 CLI 會把「Code Mode host 故意停用」與「skip_host_skill_discovery 實驗旗標」告示輸出成 `item.error`。adapter 只容許這兩種已辨識告示，其餘錯誤、未知事件、工具執行、非完整 turn 及非零退出均拒絕。未來 CLI 改變協定或設定時需重新 probe，不能靜默放寬。

來源 ID 有效只證明答案引用已提供知識，不足以證明每一句自然語言都正確。本版保留來源、退款及動作聲稱檢查；商戶應先用已核對知識試用，人工可以隨時接手。自動生成、自動答案及渠道發送分別授權。

## 尚未由以上結果證明

合成資料的模型推理與假發送器成功，不代表真正客戶收到 WhatsApp 回覆。仍需用已授權的另一個 WhatsApp 帳戶傳入問題，讀回同一來訊，並在收件手機核對實際結果。自己傳自己的只讀收件測試不會啟動此自動回覆。

本機連線不代表私人工作室已安裝或雲端持續運行；原生背景工作也不等於自動控制當前左側聊天、背景 DOT 或通用跨 AI 接續。不同機器需重新核對 CLI、登入、額度及服務生命週期。
